A command-line (CLI) installation manual for Windows / macOS / Linux, covering the two major AI coding assistants. Compiled in October 2026. Commands and versions follow the official docs; if anything here differs from the official pages, the official pages win. How to read: if you only want to install one tool, jump straight to that section; if you want to know “should I still use npm”, read the “Start Here” section.

Start Here: The Three Most Common Questions

Q1: Do I still need to install via npm?

Tool Verdict
Claude Code No. The official docs list the Native Install as Recommended, and npm has been moved to “Advanced installation options”. Moreover, only the native install updates automatically in the background — Homebrew / WinGet / npm all require manual upgrades. New users should avoid npm.
OpenCode Optional. The official project offers an install script, standalone native binaries, and npm. Users who already have Node.js will find npm the least effort; if you want no Node.js dependency at all, download the standalone binary.

Q2: Are there native installers / binaries?

Both exist.

  • Claude Code: one command with the native installer. No Node.js and no administrator privileges required — it configures PATH automatically and updates in the background.
  • OpenCode: the project ships standalone binaries for each platform (zip / tar.gz) plus an install script; however, on Windows the install script depends on a bash environment (WSL or Git Bash), which is why the official docs recommend WSL first for Windows.

Q3: How do I choose among the three approaches?

In one sentence: use the official native installer whenever you can; if network or system restrictions block you, fall back to a system package manager (WinGet / Homebrew / choco / scoop), and treat npm as the last resort.

Native Install Commands

Platform Command
Windows (PowerShell) irm https://claude.ai/install.ps1 | iex
Windows (CMD) curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash

Tip: To tell which terminal you are in — the PowerShell prompt looks like PS C:\> and the CMD prompt looks like C:\>. The two commands cannot be swapped: running the CMD command in PowerShell reports The token '&&' is not a valid statement separator; running the PowerShell command in CMD reports 'irm' is not recognized.

Selecting a release channel or version (accepted values: stable, latest, or a specific version such as 2.1.89; the default is latest):

Platform Command
Windows (PowerShell) & ([scriptblock]::Create((irm https://claude.ai/install.ps1))) stable
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash -s -- stable

What the Installer Does Behind the Scenes

Knowing the flow helps you tell “stuck” from “working”:

  1. Validate the system architecture (reject 32-bit Windows); pick the ARM64 or x64 binary automatically.
  2. Read the current version number from downloads.claude.ai.
  3. Download that version’s manifest.json and extract the SHA256 checksum for your platform.
  4. Download the binary to a local temporary directory.
  5. Verify the SHA256; on mismatch, delete the file and abort.
  6. Install into your user directory and write PATH.
  7. Delete temporary files and print a completion message.

⚠️ Two things that are easy to misjudge

  • There is no progress bar at any point, so it looks frozen while it is in fact downloading; it usually finishes within tens of seconds.
  • The completion marker is a green line reading Installation complete!.

Installation Locations

Platform Executable Data directory
Windows %USERPROFILE%\.local\bin\claude.exe %USERPROFILE%\.local\share\claude
macOS / Linux / WSL ~/.local/bin/claude ~/.local/share/claude

User configuration and session data live in ~/.claude/ (on Windows, %USERPROFILE%\.claude) and ~/.claude.json.

Verifying the Installation 

1
2

claude --version     # should print a version number
claude doctor        # environment self-check (first choice for troubleshooting)

Important: after installing, close and reopen your terminal. The PATH just written by the installer is not visible to windows that are already open.

If you get “command not found” (command not found / The term 'claude' is not recognized as the name of a cmdlet):

1
2
3

# Windows PowerShell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"                                  # ① is the binary installed?
[Environment]::GetEnvironmentVariable('Path','User') -split ';' | Select-String 'local\\bin'   # ② does PATH include it?

If ① is True while ② is empty, add it to the user-level PATH manually (no administrator needed, just append):

1
2

$p = [Environment]::GetEnvironmentVariable('Path','User')
[Environment]::SetEnvironmentVariable('Path', "$env:USERPROFILE\.local\bin;$p", 'User')

On macOS / Linux the same idea applies: add export PATH="$HOME/.local/bin:$PATH" to ~/.bashrc / ~/.zshrc.

First Run and Login 

1
2

cd your-project-directory
claude

The first launch starts a guided flow: choose a login method (a Claude subscription account, or an API key from the Anthropic Console) → finish authorization in the browser → configuration is written to ~/.claude/.

Update Strategy and Release Channels

  • Native install: updates automatically in the background, no intervention needed.
  • Release channels:
    • stable — the stable channel, usually about a week behind the newest version, and it skips releases with major regressions;
    • latest — the newest channel, available as soon as a version ships.
  • Update commands for the other methods: brew upgrade claude-code / winget upgrade Anthropic.ClaudeCode / npm update -g @anthropic-ai/claude-code.

Uninstalling

Install method Uninstall command
Native (Windows PowerShell) Remove-Item -Path "$env:USERPROFILE\.local\bin\claude.exe" -Force and Remove-Item -Path "$env:USERPROFILE\.local\share\claude" -Recurse -Force
Native (macOS / Linux / WSL) rm -f ~/.local/bin/claude and rm -rf ~/.local/share/claude
Homebrew brew uninstall --cask claude-code (use claude-code@latest for the latest channel)
WinGet winget uninstall Anthropic.ClaudeCode
npm npm uninstall -g @anthropic-ai/claude-code

Cleaning up configuration files (⚠️ this also deletes all settings, authorized tools, MCP configuration and session history):

Platform Command
Windows (PowerShell) Remove-Item -Path "$env:USERPROFILE\.claude" -Recurse -Force; Remove-Item -Path "$env:USERPROFILE\.claude.json" -Force
macOS / Linux / WSL rm -rf ~/.claude; rm ~/.claude.json

If the VS Code extension, the JetBrains plugin or the desktop app is still installed, they will recreate ~/.claude/; to remove it completely you must uninstall them first.

Troubleshooting Quick Reference

Symptom Cause and fix
command not found: claude / not recognized The install directory is not in PATH — reopen the terminal; if it still fails, see “Verifying the Installation” above
'irm' is not recognized You ran a PowerShell command in CMD
The token '&&' is not a valid statement separator You ran a CMD command in PowerShell
Download timeout / Failed to get a valid version from downloads.claude.ai Network or region issue: configure a proxy and retry, e.g. export HTTPS_PROXY=http://127.0.0.1:port (Windows: $env:HTTPS_PROXY="http://127.0.0.1:port")
Checksum verification failed Corrupted download; run the install command again
Bash tool unavailable on Windows Install Git for Windows: Claude Code prefers Git Bash and falls back to PowerShell as its shell tool when Git Bash is absent
Installed several times and behaviour is odd Multiple installs may coexist (e.g. the npm build plus the native build); use claude doctor to check for conflicting installations

Installing OpenCode

Website: https://opencode.ai | Repository: https://github.com/anomalyco/opencode

Note on the project’s history: it originally belonged to the sst organization and has since moved to anomalyco. The old link github.com/sst/opencode redirects automatically — it is not an impersonation site.

First, Understand V1 vs V2

OpenCode currently has two parallel product lines, and both use the opencode command, so they cannot coexist (you cannot install both):

V1 (stable) V2 (beta)
Install script curl -fsSL https://opencode.ai/install | bash curl -fsSL https://opencode.ai/v2/install | bash
npm package opencode-ai @opencode/cli
Homebrew brew install anomalyco/tap/opencode brew install anomalyco/tap/opencode-v2
Windows package managers choco / scoop supported Not supported
Docs https://opencode.ai/docs https://opencode.ai/v2/docs

Recommendation: V2 is still in beta and explicitly states that Windows package managers are unsupported. Choose V1 for stability; try V2 only if you want an early look, and remember it cannot coexist with V1.

V1 Installation Methods

Method Command
Install script (recommended) curl -fsSL https://opencode.ai/install | bash
npm npm install -g opencode-ai
pnpm / yarn / bun pnpm install -g opencode-ai / yarn global add opencode-ai / bun install -g opencode-ai
macOS / Linux (Homebrew) brew install anomalyco/tap/opencode
Arch Linux sudo pacman -S opencode (stable) or paru -S opencode-bin (latest)
Windows (WSL, officially recommended) Use the script or npm inside WSL
Windows (Chocolatey / Scoop) choco install opencode / scoop install opencode
Windows (npm) npm install -g opencode-ai
Docker docker run -it --rm ghcr.io/anomalyco/opencode

V2 Installation Methods

Method Command
Install script curl -fsSL https://opencode.ai/v2/install | bash
npm npm install -g @opencode/cli
bun bun install -g --trust @opencode/cli
pnpm pnpm add -g --allow-build=@opencode/cli @opencode/cli
yarn yarn global add @opencode/cli
Homebrew brew install anomalyco/tap/opencode-v2
Standalone binary Grab the archive for your platform from the download page or GitHub Releases

When installing via npm / bun / pnpm, the package’s postinstall script automatically selects the native binary for the current platform. bun and pnpm block build scripts by default, which is why the official commands include --trust / --allow-build.

Three Things Windows Users Should Know

  1. WSL is officially recommended first: best performance and compatibility.
  2. The install script needs bash: curl ... | bash will not run in a plain Windows terminal; you need WSL or Git Bash.
  3. V2 does not support Windows package managers: the choco / scoop route is unavailable on V2; use npm or the standalone binary instead.

Install Directory Priority

The install script picks its destination in this order:

  1. $OPENCODE_INSTALL_DIR
  2. $XDG_BIN_DIR
  3. $HOME/bin
  4. $HOME/.opencode/bin (the default fallback)

Example:

1

OPENCODE_INSTALL_DIR=/usr/local/bin curl -fsSL https://opencode.ai/install | bash

Verifying and Configuring 

1
2

opencode --version    # print the version
opencode              # start the TUI inside a project directory

Once launched, use /connect inside the TUI to configure model providers (the official OpenCode Zen is recommended, but any compatible provider works).

Uninstalling

  • Script / standalone binary install: delete the opencode executable from the install directory chosen above and remove that directory from PATH.
  • npm install: npm uninstall -g opencode-ai (or @opencode/cli).
  • Homebrew: brew uninstall opencode (or opencode-v2).
  • Configuration directories: ~/.config/opencode/ and ~/.local/share/opencode/ can be deleted as needed.

Desktop Version (Beta)

If you would rather not use the terminal, the project also offers a desktop app: opencode-desktop-windows-x64.exe for Windows, .dmg for macOS, and .deb / .rpm / .AppImage for Linux; see the official docs for the download page.

Comparing the Two and How to Choose

Dimension Claude Code OpenCode
Made by Anthropic (official) Anomaly community, open source (MIT)
Model support Primarily the Claude family (also supports compatible API endpoints) Any provider (including local/self-hosted)
Installation difficulty Very low (one command, automatic updates built in) Medium (pick a method per platform/version)
Windows experience Good native support (installing Git for Windows is advised) WSL recommended
Open source Client is closed source Fully open source
Best for People who want “works out of the box + official support” People who want “swappable models, self-hosting, editable source”

How to choose

  • Just want to get going fast and you have an Anthropic account → Claude Code (native install).
  • Want third-party models, want to save money, want to tinker → OpenCode (V1 stable).
  • The two are similar in positioning, so you can install both: Claude Code lives in your user directory (~/.local/bin) while OpenCode goes through npm or its own directory, so they do not interfere.

Security and Compliance Notes

  1. Download only from official domains
    • Claude Code: claude.ai, code.claude.com, downloads.claude.ai
    • OpenCode: opencode.ai, github.com/anomalyco/opencode
  2. Only trust official npm package names: look-alike packages exist on npm (the OpenCode ecosystem even saw imitations such as opcpackage). Use @anthropic-ai/claude-code for Claude Code and opencode-ai (V1) / @opencode/cli (V2) for OpenCode.
  3. Verify signatures/checksums
    • Windows: Get-AuthenticodeSignature .\claude.exe, and the signer should be Anthropic, PBC.
    • macOS: codesign --verify --verbose ./claude.
    • The project also publishes a GPG-signed manifest.json that lets you verify the SHA256 of binaries on every platform.
  4. Safe habits for curl … | bash and irm … | iex: check the domain first, then run; when possible, download the script, read it, then run it (curl -fsSL <url> -o install.sh followed by less install.sh).
  5. Be careful with third-party “config switcher / relay proxy” tools: such tools often rewrite ~/.claude/settings.json, ~/.config/opencode/opencode.json and similar files, injecting a third-party baseURL and token; if they write an invalid model name or leave a stale hook behind, you get startup errors at best and leaked credentials at worst. If you must use one, write the configuration files yourself so you know what every line does.
  6. API key management: never commit keys in plaintext to a Git repository; if a key is suspected of leaking, rotate it on the relevant platform immediately.
