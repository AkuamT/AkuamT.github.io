Windows / macOS / Linux 向けのコマンドライン（CLI）インストールマニュアルです。2 大 AI コーディングアシスタントを扱います。 まとめ時期：2026 年 10 月。コマンドとバージョンは公式ドキュメントに準拠します。公式ページと異なる場合は公式を優先してください。 読み方の目安：1 つだけ入れたい場合は該当セクションへ直接どうぞ。「npm を使い続けるべきか」を知りたい場合は「まずはここから」のセクションをご覧ください。

まずはここから：よくある 3 つの疑問

Q1：npm でのインストールはまだ必要か？

ツール 結論
Claude Code 不要。公式ドキュメントは「ネイティブインストーラー（Native Install）」を Recommended としており、npm は「Advanced installation options」に移されました。さらにバックグラウンドで自動更新されるのはネイティブインストールだけで、Homebrew / WinGet / npm はいずれも手動アップグレードが必要です。新規ユーザーは npm を選ばないことをおすすめします。
OpenCode 任意。公式はインストールスクリプト、単体ネイティブバイナリ、npm の 3 通りを提供しています。すでに Node.js 環境があるなら npm が最も楽です。Node.js に一切依存したくない場合は単体バイナリをダウンロードしてください。

Q2：ネイティブのインストーラー／バイナリはあるか？

どちらにもあります。

  • Claude Code：ネイティブインストーラーの 1 コマンドで完了。Node.js も管理者権限も不要で、PATH を自動設定し、バックグラウンドで自動更新します。
  • OpenCode：各プラットフォーム向けの単体バイナリ（zip / tar.gz）とインストールスクリプトを提供しています。ただし Windows ではインストールスクリプトが bash 環境を必要とする（WSL または Git Bash）ため、公式は Windows のセクションで WSL を第一に推奨しています。

Q3：3 つの方法をどう選ぶか？

ひと言で：公式のネイティブインストーラーが使えるならそれを使う。ネットワークやシステムの制限で詰まったら OS のパッケージマネージャー（WinGet / Homebrew / choco / scoop）に退き、npm は最後の手段とする。

ネイティブインストールのコマンド

プラットフォーム コマンド
Windows（PowerShell） irm https://claude.ai/install.ps1 | iex
Windows（CMD） curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash

ヒント：どのターミナルにいるかはプロンプトで判断できます。PowerShell は PS C:\>、CMD は C:\> の形です。2 つのコマンドは互換性がありません。PowerShell で CMD のコマンドを実行すると The token '&&' is not a valid statement separator、CMD で PowerShell のコマンドを実行すると 'irm' is not recognized が返ります。

リリースチャネルやバージョンの指定（指定できる値：stable、latest、または 2.1.89 のような具体的なバージョン番号。省略時は latest）：

プラットフォーム コマンド
Windows（PowerShell） & ([scriptblock]::Create((irm https://claude.ai/install.ps1))) stable
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash -s -- stable

インストーラーは裏で何をしているか

流れを知っておくと「止まっているのか、動いているのか」を判断しやすくなります。

  1. システムアーキテクチャを検証（32 ビット Windows は拒否）。ARM64 と x64 は自動で対応バイナリを選択。
  2. downloads.claude.ai から現在のバージョン番号を取得。
  3. そのバージョンの manifest.json をダウンロードし、該当プラットフォームの SHA256 チェックサムを取り出す。
  4. バイナリをローカルの一時ディレクトリにダウンロード。
  5. SHA256 を検証し、一致しなければファイルを削除して中止。
  6. ユーザーディレクトリにインストールし、PATH を書き込む。
  7. 一時ファイルを削除し、完了メッセージを出力。

⚠️ 誤解しやすい 2 点

  • 最初から最後まで進捗バーが出ません。止まったように見えても実際はダウンロード中で、通常は数十秒で完了します。
  • 完了の目印は緑色の Installation complete! の 1 行です。

インストール先

プラットフォーム 実行ファイル データディレクトリ
Windows %USERPROFILE%\.local\bin\claude.exe %USERPROFILE%\.local\share\claude
macOS / Linux / WSL ~/.local/bin/claude ~/.local/share/claude

ユーザー設定とセッションデータは ~/.claude/（Windows では %USERPROFILE%\.claude）と ~/.claude.json にあります。

インストールの確認 

1
2

claude --version     # バージョン番号が表示されるはず
claude doctor        # 環境のセルフチェック（トラブルシューティングの第一選択）

重要：インストール後はターミナルを閉じて開き直してください。インストーラーが書き込んだ PATH は、すでに開いているウィンドウには反映されません。

コマンドが見つからない場合（command not found / 用語 'claude' は cmdlet として認識されません）：

1
2
3

# Windows PowerShell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"                                  # ① バイナリはインストール済みか
[Environment]::GetEnvironmentVariable('Path','User') -split ';' | Select-String 'local\\bin'   # ② PATH に含まれているか

① が True で ② が空の場合、ユーザーレベルの PATH に手動で追加します（管理者権限は不要、追記するだけ）：

1
2

$p = [Environment]::GetEnvironmentVariable('Path','User')
[Environment]::SetEnvironmentVariable('Path', "$env:USERPROFILE\.local\bin;$p", 'User')

macOS / Linux も同様に、export PATH="$HOME/.local/bin:$PATH" を ~/.bashrc / ~/.zshrc に書き込みます。

初回起動とログイン 

1
2

cd あなたのプロジェクトディレクトリ
claude

初回起動時はガイド付きの流れになります：ログイン方法を選択（Claude のサブスクリプションアカウント、または Anthropic Console の API Key）→ ブラウザで認可を完了 → 設定が ~/.claude/ に書き込まれます。

更新方針とリリースチャネル

  • ネイティブインストール：バックグラウンドで自動更新。操作は不要。
  • リリースチャネル：
    • stable——安定チャネル。通常は最新版より約 1 週間遅れ、重大なリグレッションのあるバージョンはスキップされます；
    • latest——最新チャネル。新バージョンが出た瞬間に取得できます。
  • その他の方法の更新コマンド：brew upgrade claude-code / winget upgrade Anthropic.ClaudeCode / npm update -g @anthropic-ai/claude-code。

アンインストール

インストール方法 アンインストールコマンド
ネイティブ（Windows PowerShell） Remove-Item -Path "$env:USERPROFILE\.local\bin\claude.exe" -Force と Remove-Item -Path "$env:USERPROFILE\.local\share\claude" -Recurse -Force
ネイティブ（macOS / Linux / WSL） rm -f ~/.local/bin/claude と rm -rf ~/.local/share/claude
Homebrew brew uninstall --cask claude-code（latest チャネルなら claude-code@latest）
WinGet winget uninstall Anthropic.ClaudeCode
npm npm uninstall -g @anthropic-ai/claude-code

設定ファイルの削除（⚠️ すべての設定、認可済みツール、MCP 設定、セッション履歴も一緒に削除されます）：

プラットフォーム コマンド
Windows（PowerShell） Remove-Item -Path "$env:USERPROFILE\.claude" -Recurse -Force；Remove-Item -Path "$env:USERPROFILE\.claude.json" -Force
macOS / Linux / WSL rm -rf ~/.claude；rm ~/.claude.json

VS Code 拡張、JetBrains プラグイン、デスクトップアプリがまだインストールされている場合、それらが ~/.claude/ を再作成します。完全に消すには先にそれらをアンインストールしてください。

よくある問題の早見表

症状 原因と対処
command not found: claude / 認識されない インストールディレクトリが PATH に入っていない——ターミナルを開き直す。それでもだめなら上記の「インストールの確認」を参照
'irm' is not recognized CMD で PowerShell のコマンドを実行した
The token '&&' is not a valid statement separator PowerShell で CMD のコマンドを実行した
ダウンロードがタイムアウト / Failed to get a valid version from downloads.claude.ai ネットワークまたは地域の問題。プロキシを設定して再試行。例：export HTTPS_PROXY=http://127.0.0.1:ポート（Windows：$env:HTTPS_PROXY="http://127.0.0.1:ポート"）
Checksum verification failed ダウンロードが壊れている。インストールコマンドを再実行
Windows で Bash ツールが使えない Git for Windows をインストールする。Claude Code は Git Bash を優先し、未インストールならシェルツールとして PowerShell にフォールバックします
何度もインストールして挙動がおかしい 複数のインストールが併存している可能性がある（npm 版とネイティブ版など）。claude doctor で競合を確認

OpenCode のインストール

公式サイト：https://opencode.ai ｜ リポジトリ：https://github.com/anomalyco/opencode

ブランドの沿革に注意：このプロジェクトは元々 sst 組織に属していましたが、現在は anomalyco に移管されました。旧リンク github.com/sst/opencode は自動でリダイレクトされます。偽サイトではありません。

まず V1 と V2 を区別する

OpenCode には現在 2 つの並行する製品ラインがあり、どちらも opencode というコマンドを使うため共存できません（同時にインストールできません）：

V1（stable） V2（beta）
インストールスクリプト curl -fsSL https://opencode.ai/install | bash curl -fsSL https://opencode.ai/v2/install | bash
npm パッケージ名 opencode-ai @opencode/cli
Homebrew brew install anomalyco/tap/opencode brew install anomalyco/tap/opencode-v2
Windows パッケージマネージャー choco / scoop に対応 非対応
ドキュメント https://opencode.ai/docs https://opencode.ai/v2/docs

推奨：V2 はまだ beta で、Windows のパッケージマネージャーが非対応であると明言されています。安定性を求めるなら V1 を選んでください。試したい場合のみ V2 を検討し、V1 と共存できない点に注意してください。

V1 のインストール方法

方法 コマンド
インストールスクリプト（推奨） curl -fsSL https://opencode.ai/install | bash
npm npm install -g opencode-ai
pnpm / yarn / bun pnpm install -g opencode-ai / yarn global add opencode-ai / bun install -g opencode-ai
macOS / Linux（Homebrew） brew install anomalyco/tap/opencode
Arch Linux sudo pacman -S opencode（安定版）または paru -S opencode-bin（最新版）
Windows（WSL、公式推奨） WSL 内で上記のスクリプトまたは npm を使用
Windows（Chocolatey / Scoop） choco install opencode / scoop install opencode
Windows（npm） npm install -g opencode-ai
Docker docker run -it --rm ghcr.io/anomalyco/opencode

V2 のインストール方法

方法 コマンド
インストールスクリプト curl -fsSL https://opencode.ai/v2/install | bash
npm npm install -g @opencode/cli
bun bun install -g --trust @opencode/cli
pnpm pnpm add -g --allow-build=@opencode/cli @opencode/cli
yarn yarn global add @opencode/cli
Homebrew brew install anomalyco/tap/opencode-v2
単体バイナリ 公式のダウンロードページまたは GitHub Releases から該当プラットフォームのアーカイブを取得

npm / bun / pnpm でインストールする場合、パッケージ内の postinstall スクリプトが現在のプラットフォームのネイティブバイナリを自動選択します。bun と pnpm はデフォルトでビルドスクリプトをブロックするため、公式コマンドには --trust / --allow-build が付いています。

Windows ユーザーの 3 つの注意点

  1. 公式は WSL を第一に推奨：性能と機能の互換性が最も良いです。
  2. インストールスクリプトには bash が必要：curl ... | bash は素の Windows ターミナルでは動きません。WSL か Git Bash が必要です。
  3. V2 は Windows のパッケージマネージャーに対応していない：choco / scoop は V2 では使えません。V2 では npm か単体バイナリを使ってください。

インストール先ディレクトリの優先順位

インストールスクリプトは次の順序で配置先を選びます。

  1. $OPENCODE_INSTALL_DIR
  2. $XDG_BIN_DIR
  3. $HOME/bin
  4. $HOME/.opencode/bin（デフォルトのフォールバック）

例：

1

OPENCODE_INSTALL_DIR=/usr/local/bin curl -fsSL https://opencode.ai/install | bash

確認と設定 

1
2

opencode --version    # バージョンを表示
opencode              # プロジェクトディレクトリで TUI を起動

起動後は TUI 内で /connect を使ってモデルプロバイダーを設定します（公式の OpenCode Zen が推奨ですが、互換性のある任意の provider も利用できます）。

アンインストール

  • スクリプト / 単体バイナリでのインストール：上記のインストール先ディレクトリにある opencode 実行ファイルを削除し、そのディレクトリを PATH から外します。
  • npm でのインストール：npm uninstall -g opencode-ai（または @opencode/cli）。
  • Homebrew：brew uninstall opencode（または opencode-v2）。
  • 設定ディレクトリ：~/.config/opencode/、~/.local/share/opencode/ は必要に応じて削除できます。

デスクトップ版（Beta）

ターミナルを使いたくない場合、公式はデスクトップアプリも提供しています。Windows は opencode-desktop-windows-x64.exe、macOS は .dmg、Linux は .deb / .rpm / .AppImage です。ダウンロードページは公式ドキュメントを参照してください。

両者の比較と選択の指針

観点 Claude Code OpenCode
提供元 Anthropic（公式） Anomaly コミュニティのオープンソース（MIT）
モデル対応 主に Claude シリーズ（互換 API エンドポイントも可） 任意の provider（ローカル・自前構築を含む）
インストール難易度 非常に低い（1 コマンド、自動更新内蔵） 中（プラットフォーム・バージョンごとに方法を選ぶ）
Windows の体験 ネイティブ対応が良好（Git for Windows の導入を推奨） WSL を推奨
オープンソース クライアントはクローズド 完全にオープンソース
向いている人 「すぐ使えて公式サポート」を求める人 「モデルを差し替え、セルフホストし、ソースを改変したい」人

選択の指針

  • 早く使い始めたい、Anthropic アカウントがある → Claude Code（ネイティブインストール）。
  • サードパーティのモデルを使いたい、コストを抑えたい、いじりたい → OpenCode（V1 stable）。
  • 両者は機能の位置づけが似ているので、両方入れても構いません。Claude Code はユーザーディレクトリ（~/.local/bin）、OpenCode は npm か独自ディレクトリに入るため、互いに干渉しません。

セキュリティとコンプライアンスの注意

  1. 公式ドメインからのみダウンロードする
    • Claude Code：claude.ai、code.claude.com、downloads.claude.ai
    • OpenCode：opencode.ai、github.com/anomalyco/opencode
  2. npm のパッケージ名は公式のものだけを信じる：npm には同名の偽パッケージがあります（OpenCode のエコシステムでは opcpackage などの模倣パッケージが実際に出現しました）。Claude Code は @anthropic-ai/claude-code、OpenCode は opencode-ai（V1）/ @opencode/cli（V2）です。
  3. 署名・チェックサムの検証
    • Windows：Get-AuthenticodeSignature .\claude.exe。署名者は Anthropic, PBC であるべきです。
    • macOS：codesign --verify --verbose ./claude。
    • 公式は GPG 署名付きの manifest.json も提供しており、全プラットフォームのバイナリの SHA256 を検証できます。
  4. curl … | bash と irm … | iex の安全な習慣：まずドメインを確認してから実行する。可能なら先にスクリプトをダウンロードして読み、それから実行する（curl -fsSL <url> -o install.sh の後に less install.sh）。
  5. サードパーティの「設定切替 / 中継プロキシ」ツールは慎重に：これらは ~/.claude/settings.json や ~/.config/opencode/opencode.json などを直接書き換え、サードパーティの baseURL と token を書き込むことがあります。無効なモデル名や残留した hook が入ると、起動エラー程度ならまだしも、認証情報の漏洩につながります。使うなら設定ファイルは自分で書き、各行が何をしているか理解してください。
  6. API Key の管理：Key を平文で Git リポジトリにコミットしない。漏洩が疑われたら、ただちに対応プラットフォームでローテーションする。
