先搞懂：安裝到底在裝什麼

不管哪種方式，安裝一個命令列工具，本質上只做三件事：

  1. 把可執行檔放到你電腦的某個目錄裡（例如 claude.exe、opencode）。
  2. 告訴系統這個目錄在哪（也就是設定 PATH），這樣你在任何地方敲 claude 都能找到它。
  3. 可能順帶寫一些設定檔（例如 ~/.claude/、~/.config/opencode/）。

不同安裝方式的差別，只是**「誰來幫你做這三件事」**：

  • 官方腳本：官方寫好的程式幫你做。
  • 套件管理器：一個叫「套件管理器」的軟體幫你做。
  • 手動下載：你自己做。
  • Docker：把它裝進一個隔離盒子裡，不裝進你的主系統。

理解這一點，下面所有方式都好懂了。

八種安裝方式逐個講

官方一鍵腳本

長什麼樣：

1
2
3
4
5
6
7
8

# macOS / Linux / WSL
curl -fsSL https://xxx.com/install.sh | bash

# Windows PowerShell
irm https://xxx.com/install.ps1 | iex

# Windows CMD
curl -fsSL https://xxx.com/install.cmd -o install.cmd && install.cmd && del install.cmd

逐字拆解：

  • curl：一個下載工具，-fsSL 是「安靜、失敗就報錯、跟著跳轉、顯示錯誤」。
  • | bash：把下載到的內容，直接交給 bash 去執行。
  • irm：PowerShell 裡的下載命令（Invoke-RestMethod 的縮寫）。
  • | iex：把下載到的內容，直接交給 iex 執行（Invoke-Expression 的縮寫）。

所以 irm ... | iex 和 curl ... | bash 是同一個思路的兩種平台寫法：下載腳本 → 立刻執行。

它幫你做了什麼： 自動判斷你的系統（Windows 還是 Mac、64 位元還是 ARM）、下載對應版本、校驗檔案、放到目錄、設好 PATH。你只敲一行。

優點： 最省事；通常自帶自動更新；不需要預先安裝 Node.js 等執行環境。

缺點： 「下載即執行」，執行前你看不到腳本內容；必須確認網域是官方的。

適合誰： 想最快裝好、不介意信任官方腳本的人。這是目前大多數 AI CLI 工具的首推方式。

系統套件管理器

長什麼樣：

工具 平台 範例
Homebrew macOS / Linux brew install xxx
WinGet Windows winget install xxx
Chocolatey Windows choco install xxx
Scoop Windows scoop install xxx
apt Debian / Ubuntu sudo apt install xxx
dnf Fedora sudo dnf install xxx
pacman Arch Linux sudo pacman -S xxx
apk Alpine sudo apk add xxx

它是什麼： 作業系統或社群維護的「軟體倉庫」。你告訴它要裝什麼，它自己去倉庫下載、解壓、設定、登記，以後升級卸載也歸它管。

優點： 升級卸載規範；和系統整合好；不用記安裝路徑。

缺點： 倉庫裡的版本常常落後；很多新出的 AI CLI 工具根本沒進這些倉庫。

適合誰： 已經習慣用套件管理器的人；macOS 使用者用 Homebrew 尤其順手。

Windows 使用者注意： WinGet 是系統自帶的，Chocolatey 和 Scoop 需要先單獨安裝。三者不要混用同一個軟體，否則可能出現「裝了兩份、行為詭異」。

語言套件管理器（npm / pip / cargo 等）

長什麼樣：

1
2
3
4
5

npm install -g @anthropic-ai/claude-code   # Node.js 的套件管理器
npm install -g opencode-ai
pip install xxx                             # Python 的套件管理器
cargo install xxx                           # Rust 的套件管理器
go install xxx                              # Go 的套件管理器

它是什麼： 每門程式語言都有自己的「應用商店」。npm 是 Node.js 的，pip 是 Python 的，cargo 是 Rust 的。-g 表示「全域安裝」，也就是裝到系統裡，而不是只裝到目前專案。

優點： 如果你已經有 Node.js / Python / Rust 環境，這是最順手的；跨平台一致。

缺點：

  • 需要先裝對應的執行環境（例如 npm 要先有 Node.js）；
  • 全域套件升級通常要手動敲命令；
  • npm 上存在同名山寨套件，必須認準官方套件名稱。

適合誰： 本來就寫程式、電腦裡已經有 Node.js 等環境的人。

你熟悉的 npm 就屬於這一類。 它不是一個「安裝工具」，而是一個「語言生態的套件管理器」。

獨立二進位檔 / 壓縮包

長什麼樣：

去官網或 GitHub Releases 下載：

  • Windows：xxx-windows-x64.zip、.exe
  • macOS：xxx-macos-arm64.tar.gz、.dmg
  • Linux：.tar.gz、.deb、.rpm、.AppImage

下載後解壓，把裡面的可執行檔放到某個目錄，再自己把這個目錄加進 PATH。

它是什麼： 官方直接給你編譯好的「成品」，不經過任何中間商。

優點： 完全不依賴 Node.js 或套件管理器；可以精確控制版本；離線也能裝。

缺點： 升級要自己重新下載替換；PATH 要自己設；下錯架構（x64 / ARM64）會跑不起來。

適合誰： 不想裝任何執行環境、想要乾淨可控、或者網路受限裝不了腳本的人。

容器 / Docker

長什麼樣：

1

docker run -it --rm ghcr.io/anomalyco/opencode

它是什麼： Docker 是一個「隔離盒子」。工具裝在盒子裡，不碰你的主系統。-it 表示互動式終端，--rm 表示離開後自動刪除這個盒子。

優點： 乾淨、可重現、不污染系統；換電腦一條命令就能還原環境。

缺點： 要先裝 Docker；桌面類工具不一定適合；檔案路徑對應要額外設定。

適合誰： 開發者、想隔離環境的人、在伺服器上部署的人。一般使用者通常不需要。

桌面應用程式 / 圖形安裝包

長什麼樣： 雙擊 .exe、.msi、.dmg、.deb、.rpm、.AppImage。

它是什麼： 不走命令列，直接用圖形介面安裝的版本。

優點： 對不熟悉終端的人最友善；有介面，能點按鈕。

缺點： 不一定有 CLI 的全部能力；更新方式各平台不同；有些工具只提供 CLI，沒有桌面版。

適合誰： 完全不想碰終端的人。

從原始碼編譯安裝

長什麼樣：

1
2
3

git clone https://github.com/xxx/xxx
cd xxx
make && make install

或者 cargo build --release、go build。

它是什麼： 拿到原始碼，自己在你電腦上編譯成可執行檔。

優點： 可以改程式碼、可以針對自己的平台最佳化、可以裝還沒發布的版本。

缺點： 需要編譯工具鏈，耗時長，升級麻煩，容易報錯。

適合誰： 開發者、想改原始碼的人。一般使用者不要選。

應用商店 / 外掛市集

長什麼樣：

  • 在 VS Code 擴充市集裡搜外掛；
  • 在 JetBrains 外掛市集裡搜外掛；
  • 在 Microsoft Store / Mac App Store 裡搜應用程式；
  • 瀏覽器擴充商店。

它是什麼： 裝在某個宿主軟體裡的「外掛版」，不是獨立 CLI。

優點： 安裝最簡單，和宿主軟體整合好。

缺點： 能力受宿主軟體限制；卸載宿主軟體時外掛也沒了；有些外掛會重新建立設定檔。

適合誰： 只想在某個編輯器裡用，不想單獨裝 CLI 的人。

方式 典型命令 需要預裝 自動更新 適合誰

系統套件管理器 brew / winget / choco / scoop / apt 對應套件管理器 隨套件管理器 已習慣套件管理器的人
語言套件管理器 npm -g / pip / cargo 對應執行環境 手動 已有 Node/Python/Rust 環境的人
獨立二進位檔 下載 zip / tar.gz 無 手動 不想依賴執行環境、要控版本
容器 / Docker docker run … Docker 重新拉映像檔 想隔離環境、可重現
桌面應用程式 雙擊 .exe / .dmg 無 應用程式內更新 不想用終端的人

一句話選擇建議：

能用官方一鍵腳本就用官方一鍵腳本；被網路或系統限制卡住，再退到系統套件管理器；npm 等語言套件管理器作為最後選項；完全不想依賴執行環境就用獨立二進位檔；不想碰終端就用桌面應用程式。

術語小辭典

詞 意思
CLI Command Line Interface，命令列介面。就是你在終端裡敲命令用的工具。
終端 / Terminal 敲命令的那個黑框或視窗。Windows 上有 PowerShell、CMD、Windows Terminal。
PATH 環境變數，告訴系統「去哪些目錄找可執行檔」。設不好就會提示 command not found。
npm Node.js 的套件管理器，不是安裝方式本身，是「語言套件管理器」這一類裡最有名的一個。
irm PowerShell 裡的 Invoke-RestMethod，用來從網路下載內容。irm ... | iex = 下載腳本並執行。
curl 跨平台的下載工具。curl ... | bash = 下載腳本並執行。
iex PowerShell 裡的 Invoke-Expression，把一段文字當作程式碼執行。
二進位檔 / Binary 已經編譯好的可執行檔，雙擊或敲命令就能跑。
執行環境 某門語言跑起來需要的環境，例如 Node.js 是 JavaScript 的執行環境。
全域安裝 裝到整個系統都能用，而不是只裝到某個專案資料夾。npm 裡用 -g 表示。
Docker 一個「隔離盒子」工具，把軟體裝在盒子裡，不碰主系統。
倉庫 / Repository 存放套件或原始碼的地方。GitHub 是最常見的程式碼倉庫。
Releases GitHub 上「發布版本」的頁面，通常放編譯好的壓縮包。

安全提醒

  1. 只從官方網域下載。 執行 curl … | bash 或 irm … | iex 前，先看清網域。

  2. npm 套件名稱只認官方的。 npm 上存在同名山寨套件，裝錯可能洩露憑證。

  3. curl | bash 的習慣： 有條件的話先下載腳本、讀一遍再執行：

    1
2
3

    curl -fsSL <url> -o install.sh
less install.sh
bash install.sh

  4. 校驗簽章 / 校驗和。 官方通常提供 SHA256 或 GPG 簽章，重要工具建議校驗。

  5. 謹慎使用第三方「設定切換 / 中轉代理」工具。 它們常會改寫你的設定檔，寫入第三方位址和權杖，輕則報錯，重則憑證外洩。

  6. API Key 不要提交進 Git 倉庫。 一旦疑似洩露，立即到對應平台輪換。
