面向 Windows / macOS / Linux 的命令列（CLI）安裝手冊，涵蓋兩大 AI 編程助手。 整理時間：2026 年 10 月。命令與版本以官方文件為準，若與官方頁面不一致，以官方為準。 閱讀建議：只想裝一個工具，直接跳到對應章節；想先了解「該不該繼續用 npm」，看「先看這裡」一節。

先看這裡：三個最常問的問題

Q1：還需要用 npm 安裝嗎？

工具 結論
Claude Code 不需要。官方文件已把「原生安裝器（Native Install）」列為 Recommended，npm 被挪到「Advanced installation options」。而且只有原生安裝會背景自動更新，Homebrew / WinGet / npm 三條路都要手動升級。新使用者不建議再走 npm。
OpenCode 可選。官方同時提供安裝腳本、獨立原生二進位檔、npm 三種方式。已有 Node.js 環境的使用者走 npm 最省事；想完全不依賴 Node.js 就下獨立二進位檔。

Q2：有原生安裝包／二進位檔嗎？

兩個都有。

  • Claude Code：原生安裝器一條命令搞定，不需要 Node.js，也不需要管理員權限，會自動設定 PATH 並在背景自動更新。
  • OpenCode：官方提供各平台的獨立二進位檔（zip / tar.gz），也有安裝腳本；但 Windows 上安裝腳本依賴 bash 環境（WSL 或 Git Bash），官方因此在 Windows 章節首推 WSL。

Q3：三者裝法怎麼選？

一句話：能用官方原生安裝器就用原生安裝器；被網路或系統限制卡住時，再退到系統套件管理器（WinGet / Homebrew / choco / scoop），npm 作為最後選項。

Claude Code 安裝

系統需求

項目 需求
作業系統 macOS 13.0+ / Windows 10 1809+ 或 Windows Server 2019+ / Ubuntu 20.04+ / Debian 10+ / Alpine Linux 3.19+
硬體 4 GB+ 記憶體；x64 或 ARM64 處理器（不支援 32 位元 Windows）
網路 必須連網
Shell Bash、Zsh、PowerShell 或 CMD
附加依賴 ripgrep——Claude Code 通常自帶，若程式碼搜尋異常見官方排障頁
地區 需位於 Anthropic 支援的國家／地區

安裝方式總覽

方式 自動更新 適用平台
原生安裝器（推薦） ✅ 背景自動 Windows / macOS / Linux / WSL
Homebrew ❌ 需手動 brew upgrade macOS / Linux
WinGet ❌ 需手動 winget upgrade Windows
Linux 套件管理器（apt / dnf / apk） 隨套件管理器 Debian / Fedora / Alpine
npm（進階選項） ❌ 需手動升級 任何有 Node.js 的平台
桌面應用程式（圖形介面） — Windows / macOS / Linux

原生安裝命令

平台 命令
Windows（PowerShell） irm https://claude.ai/install.ps1 | iex
Windows（CMD） curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash

提示：判斷自己在哪個終端——PowerShell 的提示符長這樣 PS C:\>，CMD 的長這樣 C:\>。兩條命令不能互換：在 PowerShell 裡跑 CMD 命令會報 The token '&&' is not a valid statement separator；在 CMD 裡跑 PowerShell 命令會報 'irm' is not recognized。

指定發布通道或版本（參數取值：stable、latest、或具體版本號如 2.1.89，預設為 latest）：

平台 命令
Windows（PowerShell） & ([scriptblock]::Create((irm https://claude.ai/install.ps1))) stable
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash -s -- stable

安裝器背後做了什麼

了解流程有助於判斷「卡住了還是在幹活」：

  1. 校驗系統架構（拒絕 32 位元 Windows）；ARM64 與 x64 自動選擇對應二進位檔。
  2. 從 downloads.claude.ai 讀取目前版本號。
  3. 下載該版本的 manifest.json，取出對應平台的 SHA256 校驗和。
  4. 下載二進位檔到本機暫存目錄。
  5. 校驗 SHA256，不一致則刪除檔案並中止。
  6. 安裝到使用者目錄並寫入 PATH。
  7. 刪除暫存檔，輸出完成提示。

⚠️ 兩個容易誤判的點

  • 全程沒有進度條，看起來像卡住，實際在下載，通常幾十秒內完成。
  • 完成標誌是一行綠色的 Installation complete!。

安裝位置

平台 可執行檔 資料目錄
Windows %USERPROFILE%\.local\bin\claude.exe %USERPROFILE%\.local\share\claude
macOS / Linux / WSL ~/.local/bin/claude ~/.local/share/claude

使用者設定與工作階段資料則位於：~/.claude/（Windows 為 %USERPROFILE%\.claude）與 ~/.claude.json。

驗證安裝 

1
2

claude --version     # 應印出版本號
claude doctor        # 環境自檢（排障首選）

重要：安裝後請關閉並重新開啟終端。安裝器剛寫入的 PATH 對已經開啟的視窗不可見。

如果提示找不到命令（command not found / 無法將"claude"項辨識為 cmdlet）：

1
2
3

# Windows PowerShell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"                                  # ① 二進位檔是否已安裝
[Environment]::GetEnvironmentVariable('Path','User') -split ';' | Select-String 'local\\bin'   # ② PATH 是否包含

若 ① 為 True 而 ② 為空，手動補進使用者層級 PATH（無需管理員，附加即可）：

1
2

$p = [Environment]::GetEnvironmentVariable('Path','User')
[Environment]::SetEnvironmentVariable('Path', "$env:USERPROFILE\.local\bin;$p", 'User')

macOS / Linux 同理，把 export PATH="$HOME/.local/bin:$PATH" 寫進 ~/.bashrc / ~/.zshrc。

首次執行與登入 

1
2

cd 你的專案目錄
claude

首次啟動會進入引導流程：選擇登入方式（Claude 訂閱帳號，或 Anthropic Console 的 API Key）→ 瀏覽器完成授權 → 設定寫入 ~/.claude/。

不想用 Anthropic 官方帳號？ 可以改接第三方廠商的 Anthropic 相容端點（DeepSeek / Kimi / 智譜 GLM / 通義千問等），並直接跳過登入引導 —— 見下文「不用官方登入：接入第三方大模型 API」一節。

更新策略與發布通道

  • 原生安裝：背景自動更新，無需干預。
  • 發布通道：
    • stable——穩定通道，通常比最新版落後約一週，會跳過有重大回歸的版本；
    • latest——最新通道，新版本一發布就能拿到。
  • 其他方式的更新命令：brew upgrade claude-code / winget upgrade Anthropic.ClaudeCode / npm update -g @anthropic-ai/claude-code。

卸載

安裝方式 卸載命令
原生（Windows PowerShell） Remove-Item -Path "$env:USERPROFILE\.local\bin\claude.exe" -Force 與 Remove-Item -Path "$env:USERPROFILE\.local\share\claude" -Recurse -Force
原生（macOS / Linux / WSL） rm -f ~/.local/bin/claude 與 rm -rf ~/.local/share/claude
Homebrew brew uninstall --cask claude-code（latest 通道則為 claude-code@latest）
WinGet winget uninstall Anthropic.ClaudeCode
npm npm uninstall -g @anthropic-ai/claude-code

清理設定檔（⚠️ 會一併刪除全部設定、已授權工具、MCP 設定與工作階段歷史）：

平台 命令
Windows（PowerShell） Remove-Item -Path "$env:USERPROFILE\.claude" -Recurse -Force；Remove-Item -Path "$env:USERPROFILE\.claude.json" -Force
macOS / Linux / WSL rm -rf ~/.claude；rm ~/.claude.json

若 VS Code 擴充、JetBrains 外掛或桌面應用程式仍在安裝狀態，它們會重新建立 ~/.claude/；想徹底清除需先卸載它們。

常見問題速查

現象 原因與處理
command not found: claude / 無法辨識 安裝目錄未進 PATH —— 重開終端；仍不行參考上面「驗證安裝」一節
'irm' is not recognized 你在 CMD 裡執行了 PowerShell 命令
The token '&&' is not a valid statement separator 你在 PowerShell 裡執行了 CMD 命令
下載逾時 / Failed to get a valid version from downloads.claude.ai 網路或地區問題：設定代理後重試，例如 export HTTPS_PROXY=http://127.0.0.1:連接埠（Windows：$env:HTTPS_PROXY="http://127.0.0.1:連接埠"）
Checksum verification failed 下載損毀，重新執行安裝命令
Windows 上 Bash 工具無法使用 安裝 Git for Windows：Claude Code 會優先使用 Git Bash，未安裝時回退到 PowerShell 作為 shell 工具
裝過多次、行為詭異 可能存在多個安裝（如 npm 版 + 原生版並存），用 claude doctor 檢查衝突安裝

OpenCode 安裝

官網：https://opencode.ai ｜ 倉庫：https://github.com/anomalyco/opencode

注意品牌沿革：該專案原屬 sst 組織，現已遷移至 anomalyco。舊連結 github.com/sst/opencode 會自動跳轉，不是仿冒站點。

先搞清 V1 與 V2

OpenCode 目前有兩條並行的產品線，都使用 opencode 這個命令，無法共存（不能同時安裝）：

V1（stable） V2（beta）
安裝腳本 curl -fsSL https://opencode.ai/install | bash curl -fsSL https://opencode.ai/v2/install | bash
npm 套件名稱 opencode-ai @opencode/cli
Homebrew brew install anomalyco/tap/opencode brew install anomalyco/tap/opencode-v2
Windows 套件管理器 支援 choco / scoop 不支援
文件 https://opencode.ai/docs https://opencode.ai/v2/docs

建議：V2 仍在 beta，且明確聲明 Windows 套件管理器不受支援。追求穩定請選 V1；想嘗鮮再考慮 V2，並注意它與 V1 不能並存。

V2 安裝方式

方式 命令
安裝腳本 curl -fsSL https://opencode.ai/v2/install | bash
npm npm install -g @opencode/cli
bun bun install -g --trust @opencode/cli
pnpm pnpm add -g --allow-build=@opencode/cli @opencode/cli

Homebrew brew install anomalyco/tap/opencode-v2
獨立二進位檔 從官網下載頁或 GitHub Releases 取對應平台壓縮包

透過 npm / bun / pnpm 安裝時，套件內 postinstall 腳本會自動選擇目前平台的原生二進位檔。bun 與 pnpm 預設阻止建置腳本，因此官方命令裡帶了 --trust / --allow-build 參數。

Windows 使用者的三個注意點

  1. 官方首推 WSL：效能與功能相容性最好。
  2. 安裝腳本需要 bash：curl ... | bash 在純 Windows 終端裡跑不了，需 WSL 或 Git Bash。
  3. V2 不支援 Windows 套件管理器：choco / scoop 這條路在 V2 上不通；V2 請用 npm 或獨立二進位檔。

安裝目錄優先順序

安裝腳本按以下順序選擇落點：

  1. $OPENCODE_INSTALL_DIR
  2. $XDG_BIN_DIR
  3. $HOME/bin
  4. $HOME/.opencode/bin（預設兜底）

例：

1

OPENCODE_INSTALL_DIR=/usr/local/bin curl -fsSL https://opencode.ai/install | bash

驗證與設定 

1
2

opencode --version    # 印出版本
opencode              # 在專案目錄中啟動 TUI

啟動後在 TUI 裡用 /connect 設定模型供應商（官方推薦自家 OpenCode Zen，也支援任意相容 provider）。

卸載

  • 腳本／獨立二進位檔安裝：刪除上一步安裝目錄中的 opencode 可執行檔，並從 PATH 中移除該目錄。
  • npm 安裝：npm uninstall -g opencode-ai（或 @opencode/cli）。
  • Homebrew：brew uninstall opencode（或 opencode-v2）。
  • 設定目錄：~/.config/opencode/、~/.local/share/opencode/ 可依需求刪除。

桌面版（Beta）

不想用終端的話，官方也提供桌面應用程式：Windows 為 opencode-desktop-windows-x64.exe，macOS 為 .dmg，Linux 為 .deb / .rpm / .AppImage，下載頁見官方文件。

兩者對比與選擇建議

維度 Claude Code OpenCode
出品方 Anthropic（官方） Anomaly 社群開源（MIT）
模型支援 主要面向 Claude 系列（也支援相容 API 端點） 任意 provider（含本機／自建）
安裝難度 極低（一條命令，自帶自動更新） 中（需按平台／版本挑方式）

是否開源 客戶端閉源 完全開源

選擇建議

  • 只想盡快用起來、且有 Anthropic 帳號 → Claude Code（原生安裝）。
  • 想接第三方模型、想省錢、想折騰 → OpenCode（V1 stable）。
  • 兩者功能定位類似，可以先都裝：Claude Code 裝在使用者目錄（~/.local/bin），OpenCode 走 npm 或獨立目錄，互不干擾。

不用官方登入：接入第三方大模型 API

本節講的是 Claude Code 官方支援的機制：把請求指向你自己的 LLM 閘道，或指向第三方廠商提供的 Anthropic 相容端點（DeepSeek、Kimi、智譜 GLM、通義千問等）。它不是破解 —— 官方文件裡專門有一頁《Connect Claude Code to an LLM gateway》講這件事；設定好之後 Claude Code 就不再要求 Anthropic 官方登入。

原理：換一個位址 + 換一個憑證

Claude Code 只認一件事：Anthropic Messages API 協定。任何相容這套協定的服務，只要改幾個環境變數就能把底層模型換掉。

變數 作用 不設定的後果
ANTHROPIC_BASE_URL 請求送往的端點 請求仍送往 Anthropic 官方，第三方 Key 驗證失敗
ANTHROPIC_AUTH_TOKEN 憑證，以 Authorization: Bearer <token> 送出 401 驗證錯誤
ANTHROPIC_API_KEY 憑證的另一種形式，以 x-api-key 送出 同上（互動模式下還需一次性確認，見下文「排查表」）
ANTHROPIC_MODEL 主對話模型 回報「模型不存在」
ANTHROPIC_DEFAULT_OPUS_MODEL
ANTHROPIC_DEFAULT_SONNET_MODEL
ANTHROPIC_DEFAULT_HAIKU_MODEL
ANTHROPIC_DEFAULT_FABLE_MODEL		 各級距的模型對應 對應級距的任務失敗
CLAUDE_CODE_SUBAGENT_MODEL 子 Agent 使用的模型 子任務失敗或效果明顯變差

憑證變數該用哪個？ 官方建議：不確定對方的閘道要哪一種時，先用 ANTHROPIC_AUTH_TOKEN；若回傳 401，再換成 ANTHROPIC_API_KEY（反過來也一樣）。兩個不要同時設定。

為什麼必須設定「級距對應」？ Claude Code 會依情境請求不同級距的模型——主對話、背景摘要、子 Agent 等。第三方端點通常沒有 haiku / sonnet / opus 這些名稱，所以要把每個級距明確對應到真實模型名稱，否則對應的情境會靜默失敗（表面能聊，背景任務卻報錯）。

設定步驟

第 1 步：取得端點與模型名稱 —— 見下文「廠商設定速查表」，並以各廠官方文件為準。

第 3 步：跳過首次登入引導

編輯或新建 ~/.claude.json（Windows：C:\Users\<使用者名稱>\.claude.json），加入這一項：

2

{
  "hasCompletedOnboarding": true
}

不設定它時，Claude Code 啟動後會嘗試連線 api.anthropic.com 做登入檢查，於是出現 Unable to connect to Anthropic services. Failed to connect to api.anthropic.com: ERR_BAD_REQUEST 這類錯誤。

跨平台一次寫入（用 node 改 JSON，避免手改格式出錯）：

1

node --eval "const fs=require('fs'),p=require('path'),os=require('os');const f=p.join(os.homedir(),'.claude.json');const c=fs.existsSync(f)?JSON.parse(fs.readFileSync(f,'utf-8')):{};c.hasCompletedOnboarding=true;fs.writeFileSync(f,JSON.stringify(c,null,2),'utf-8')"

第 4 步：重啟終端 → 啟動 claude → 驗證（見下文「驗證設定是否生效」）

設定寫在哪裡的差別（關鍵）

位置 生效範圍 說明
~/.claude/settings.json 的 env 所有專案（個人層級） ✅ 推薦，官方與各廠商文件都用它
shell 環境變數（export / $env:） 目前終端及其子行程 適合臨時測試；但從桌面／開始功能表啟動的 IDE 看不到這些變數
專案 .claude/settings.json 的 env 僅該專案 ⚠️ 它在首次執行精靈和信任提示之後才生效，因此不能用來跳過登入；而且容易被提交進 git

衝突規則：settings.json 裡的 env 會覆蓋 shell 中同名的環境變數。 所以發現「改了環境變數卻不生效」時，先回頭檢查 settings.json 裡是不是有殘留舊值。

三個容易踩到的細節

  1. [1m] 後綴是有效的，表示「1M 上下文視窗」，不是筆誤——各廠文件裡都這樣寫（如 kimi-k3[1m]、glm-5.3[1m]、qwen3.7-plus[1m]）。也可以用 CLAUDE_CODE_MAX_CONTEXT_TOKENS 環境變數表達同樣的意思。
  2. DeepSeek 會自動對應模型名稱：官方文件說明，傳入不支援的模型名稱時後端會自動對應到 deepseek-flash；並且 claude-opus* → deepseek-v4-pro，claude-haiku* / claude-sonnet* → deepseek-flash。這也是它只需改一個 base_url 就能接入 Claude Code 的原因。
  3. 端點位址不要自己附加 /v1 或 /v1/messages：Claude Code 會自行拼接路徑，多寫一段往往直接 404。

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.moonshot.cn/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "YOUR_API_KEY",
    "ANTHROPIC_MODEL": "kimi-k3[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "kimi-k3[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "kimi-k3[1m]",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "kimi-k2.7-code",
    "ANTHROPIC_DEFAULT_FABLE_MODEL": "kimi-k3[1m]",
    "CLAUDE_CODE_SUBAGENT_MODEL": "kimi-k3[1m]",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000",
    "CLAUDE_CODE_EFFORT_LEVEL": "max"
  }
}

各參數的作用：

  • ANTHROPIC_DEFAULT_HAIKU_MODEL 通常搭配一個便宜快速的模型（背景摘要、小任務用），主級距搭配強模型；
  • CLAUDE_CODE_AUTO_COMPACT_WINDOW：觸發上下文自動壓縮的視窗大小，設太小會過早丟失上下文；
  • CLAUDE_CODE_EFFORT_LEVEL：推理強度，max 品質最好，也最慢最貴。

驗證設定是否生效

步驟 操作 期望結果
① 直測端點 curl <BASE_URL>/v1/messages --header "Authorization: Bearer <KEY>" --header "Content-Type: application/json" --data '{"model":"<模型>","max_tokens":1,"messages":[{"role":"user","content":"hi"}]}' 回傳合法 JSON（{"id":"msg_...","content":[...]}），而不是 HTML 錯誤頁
② 工作階段內檢查 啟動 claude 後執行 /status Anthropic base URL 行顯示你的端點；Auth token / API key 行顯示憑證來源。若顯示 Login method: <claude.ai 帳號> 表示憑證沒送到
③ 端到端 隨便送一句（如「你好」） 正常回覆、無報錯
④ 模型級距 /model 能看到你設定的模型

修改設定後必須新開終端視窗再啟動 claude，否則讀到的是舊環境。

重要提醒

  1. 別同時設定 ANTHROPIC_API_KEY 和 ANTHROPIC_AUTH_TOKEN，會衝突；Kimi 文件明確指出要把 ANTHROPIC_API_KEY 刪掉。
  2. settings.json 裡是明文 Key：不要提交進 git；專案層級設定務必寫進 .gitignore。
  3. .env 檔案不會被讀取：不要把憑證寫在 .env 裡。
  4. 換第三方 = 換資料去向：你的程式碼和對話會完整經過該廠商或中轉服務，選擇前想清楚；優先使用廠商直營端點，慎用來源不明的「中轉站」。
  5. 回到官方登入：刪掉 settings.json 中 env 裡的這些變數（或直接刪該檔案），執行 /logout，重啟 claude 即可恢復官方登入流程。
  6. 第三方「一鍵切換」工具的取捨：見下文「用圖形化工具管設定」一節 —— 它們會直接改寫 settings.json，省的是操作成本，貴的是排查成本。

用圖形化工具管設定（以 CC Switch 為例的取捨）

手寫 settings.json 對不熟悉 JSON 的人確實有門檻，於是出現了不少「設定管理 / 供應商切換」類圖形工具，其中最流行的是 CC Switch（github.com/farion1231/cc-switch，14 萬+ stars，官網 ccswitch.io）。本節的分析對這一類工具普遍適用。

它們解決什麼問題

  • 在圖形介面裡填 Base URL / API Key，不用碰 JSON，也不怕寫錯逗號；
  • 內建常見廠商範本（DeepSeek、Kimi、智譜 GLM、通義千問等）與自架閘道；
  • 一鍵切換多個供應商（官方帳號 ↔ 第三方帳號 ↔ 便宜模型）；
  • 自動幫你寫入 hasCompletedOnboarding，省掉首次登入引導；
  • 附帶備份、Skills 管理、用量統計等周邊功能。

對需要在多個供應商之間頻繁切換的使用者，這確實省事。它省的是操作成本。

需要知道的固有代價

這類工具不是「幫你改一個欄位」，而是接管你的設定檔。以 CC Switch 為例，它的官方文件與 issue 裡明確記錄了幾條「設計如此」的行為：

行為 後果
切換供應商時用完整快照重寫 live 設定檔（官方在 issue #3946 明確回覆「這是有意的設計行為」） 你自己寫在 settings.json 裡的 hooks、statusLine、permissions 等欄位會被覆蓋掉；同類 issue 還有 #2992 / #4274 / #2109 / #2871 / #3078
會寫入自己的 hook 或環境變數，有時還附帶輔助指令碼 若指令碼本體或解譯器在本機不存在，每次啟動都會報錯，且報錯位置離「設定」很遠，極難定位
一個程式同時接管多個 CLI（Claude Code / Codex / OpenCode / Gemini / Grok / Hermes 等） 任一處錯配會波及其他工具。例如寫入 OpenCode 設定的路徑與工具實際讀取的路徑不一致時，會出現「切換看似成功、實際全部落空」（issue #5945）
修改的是真實生效檔案，而非副本 出問題時，第一現場就是你在用的工作設定

注意：這通常不是「軟體品質差」，而是產品定位使然——接管式管理必然帶來「誰的欄位算數」的衝突。它確實提供備份（~/.cc-switch/backups/，以及記錄首次改寫前原檔案的 backups/live-first-write/），但備份能救檔案，救不了你排查問題時浪費的時間。

新手友善度的悖論

手寫設定 圖形化工具
上手成本 需要看懂一個 JSON 檔案 點幾下就能用
出問題時的排查 每一行都是你自己寫的，範圍很小 面對工具產生的一堆檔案 + 被覆蓋的原始設定 + 自動注入的 hook，不清楚哪一層在生效
能否腳本化排查 可以（用 diff、/status、claude doctor 逐層驗證） 通常不行（純 GUI，無命令列入口）

換句話說：它省的是操作成本，貴的是排查成本。 如果你連「設定為什麼沒生效」都還需要搜尋，那麼當工具替你寫入的內容出問題時，你會更無從下手。

決策建議

你的情況 建議
只用一個供應商長期使用 手寫一次設定就夠，之後幾個月都不用再碰。圖形介面省下的幾分鐘，不值它帶來的覆蓋風險
需要在 3 個以上供應商之間頻繁切換 這類工具的價值才真正體現，值得用，但請照下面「如果決定用，請這樣做」的方式使用
想要極簡 用上文「不用官方登入」一節的「範本 + 一條命令」，或自架「切換 = 複製一個小檔案」的指令碼，比 GUI 更快也更透明

如果決定用，請這樣做

  1. 只讓它管一個工具：用不到的 CLI（Codex / Gemini / OpenCode 等）不要打開對應面板；
  2. 關掉本機代理 / Routing：直連最少一層轉發出錯的可能；
  3. 關掉非必要的自動同步：Skills 同步、工作階段同步、外掛整合都會順手改到別的目錄；
  4. 每次切換後打開設定檔看一眼（~/.claude/settings.json）：確認 env 裡的模型名稱正確，且沒有多餘的 hooks 段；
  5. 記住備份位置：~/.cc-switch/backups/live-first-write/ 保存著「被改寫前的原始檔案」，出事從這裡撈；
  6. 切換後跑一次自檢（如 claude doctor）；
  7. 心裡有數：以上 6 條都做下來，對單一供應商使用者來說，已經比手寫一個 JSON 更麻煩了。

安全提醒

  • 這類工具會接觸到你的 API Key 和全部設定檔，務必只從官方管道下載。CC Switch 的官方站點是 ccswitch.io，官方倉庫是 github.com/farion1231/cc-switch；GitHub 上存在多個同名 fork，下載前確認作者與位址。
  • 連推薦它的雲廠商也會附上免責聲明。例如阿里雲百鍊文件在介紹它時寫道：「該工具為第三方軟體，其指令碼與程式碼不受阿里雲審核和維護，安裝使用前請自行評估其來源可信度與程式碼安全性。」
  • 無論用什麼工具，最終生效的永遠是 ~/.claude/settings.json。學會讀這個檔案，你就永遠有兜底能力。

安全與合規提醒

  1. 只從官方網域下載
    • Claude Code：claude.ai、code.claude.com、downloads.claude.ai
    • OpenCode：opencode.ai、github.com/anomalyco/opencode
  2. npm 套件名稱只認官方的：npm 上存在同名山寨套件（OpenCode 生態裡就出現過 opcpackage 等仿製套件）。Claude Code 認 @anthropic-ai/claude-code，OpenCode 認 opencode-ai（V1）/ @opencode/cli（V2）。
  3. 校驗簽章／校驗和
    • Windows：Get-AuthenticodeSignature .\claude.exe，簽署者應為 Anthropic, PBC。
    • macOS：codesign --verify --verbose ./claude。
    • 官方還提供帶 GPG 簽章的 manifest.json，可校驗所有平台二進位檔的 SHA256。
  4. curl … | bash 與 irm … | iex 的安全習慣：先看清網域，再執行；有條件的話先下載腳本、讀一遍再執行（curl -fsSL <url> -o install.sh 然後 less install.sh）。
  5. 第三方「設定切換／中轉代理」工具的取捨：詳見上文「用圖形化工具管設定」一節。核心是——它們會直接改寫 ~/.claude/settings.json、~/.config/opencode/opencode.json 等檔案，最終生效的永遠是這些檔案本身，所以務必會讀、會改、會驗證它們。
  6. API Key 管理：不要把 Key 明文提交進 Git 倉庫；一旦疑似洩露，立即到對應平台輪換。
