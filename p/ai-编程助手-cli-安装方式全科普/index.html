先搞懂：安装到底在装什么

不管哪种方式，装一个命令行工具，本质上只做三件事：

  1. 把可执行文件放到你电脑的某个目录里（比如 claude.exe、opencode）。
  2. 告诉系统这个目录在哪（也就是配置 PATH），这样你在任何地方敲 claude 都能找到它。
  3. 可能顺带写一些配置文件（比如 ~/.claude/、~/.config/opencode/）。

不同安装方式的区别，只是**“谁来帮你做这三件事”**：

  • 官方脚本：官方写好的程序帮你做。
  • 包管理器：一个叫"包管理器"的软件帮你做。
  • 手动下载：你自己做。
  • Docker：把它装进一个隔离盒子里，不装进你主系统。

理解这一点，下面所有方式都好懂了。

八种安装方式逐个讲

官方一键脚本

长什么样：

1
2
3
4
5
6
7
8

# macOS / Linux / WSL
curl -fsSL https://xxx.com/install.sh | bash

# Windows PowerShell
irm https://xxx.com/install.ps1 | iex

# Windows CMD
curl -fsSL https://xxx.com/install.cmd -o install.cmd && install.cmd && del install.cmd

逐字拆解：

  • curl：一个下载工具，-fsSL 是"安静、失败就报错、跟着跳转、显示错误"。
  • | bash：把下载到的内容，直接交给 bash 去执行。
  • irm：PowerShell 里的下载命令（Invoke-RestMethod 的缩写）。
  • | iex：把下载到的内容，直接交给 iex 执行（Invoke-Expression 的缩写）。

所以 irm ... | iex 和 curl ... | bash 是同一个思路的两种平台写法：下载脚本 → 立刻运行。

它帮你做了什么： 自动判断你的系统（Windows 还是 Mac、64 位还是 ARM）、下载对应版本、校验文件、放到目录、配好 PATH。你只敲一行。

优点： 最省事；通常自带自动更新；不需要预先装 Node.js 等运行时。

缺点： “下载即执行”，执行前你看不到脚本内容；必须确认域名是官方的。

适合谁： 想最快装好、不介意信任官方脚本的人。这是目前大多数 AI CLI 工具的首推方式。

系统包管理器

长什么样：

工具 平台 示例
Homebrew macOS / Linux brew install xxx
WinGet Windows winget install xxx
Chocolatey Windows choco install xxx
Scoop Windows scoop install xxx
apt Debian / Ubuntu sudo apt install xxx
dnf Fedora sudo dnf install xxx
pacman Arch Linux sudo pacman -S xxx
apk Alpine sudo apk add xxx

它是什么： 操作系统或社区维护的"软件仓库"。你告诉它要装什么，它自己去仓库下载、解压、配置、登记，以后升级卸载也归它管。

优点： 升级卸载规范；和系统集成好；不用记安装路径。

缺点： 仓库里的版本常常滞后；很多新出的 AI CLI 工具根本没进这些仓库。

适合谁： 已经习惯用包管理器的人；macOS 用户用 Homebrew 尤其顺手。

Windows 用户注意： WinGet 是系统自带的，Chocolatey 和 Scoop 需要先单独安装。三者不要混用同一个软件，否则可能出现"装了两份、行为诡异"。

语言包管理器（npm / pip / cargo 等）

长什么样：

1
2
3
4
5

npm install -g @anthropic-ai/claude-code   # Node.js 的包管理器
npm install -g opencode-ai
pip install xxx                             # Python 的包管理器
cargo install xxx                           # Rust 的包管理器
go install xxx                              # Go 的包管理器

它是什么： 每门编程语言都有自己的"应用商店"。npm 是 Node.js 的，pip 是 Python 的，cargo 是 Rust 的。-g 表示"全局安装"，也就是装到系统里，而不是只装到当前项目。

优点： 如果你已经有 Node.js / Python / Rust 环境，这是最顺手的；跨平台一致。

缺点：

  • 需要先装对应的运行时（比如 npm 要先有 Node.js）；
  • 全局包升级通常要手动敲命令；
  • npm 上存在同名山寨包，必须认准官方包名。

适合谁： 本来就写代码、电脑里已经有 Node.js 等环境的人。

你熟悉的 npm 就属于这一类。 它不是一个"安装工具"，而是一个"语言生态的包管理器"。

独立二进制 / 压缩包

长什么样：

去官网或 GitHub Releases 下载：

  • Windows：xxx-windows-x64.zip、.exe
  • macOS：xxx-macos-arm64.tar.gz、.dmg
  • Linux：.tar.gz、.deb、.rpm、.AppImage

下载后解压，把里面的可执行文件放到某个目录，再自己把这个目录加进 PATH。

它是什么： 官方直接给你编译好的"成品"，不经过任何中间商。

优点： 完全不依赖 Node.js 或包管理器；可以精确控制版本；离线也能装。

缺点： 升级要自己重新下载替换；PATH 要自己配；下错架构（x64 / ARM64）会跑不起来。

适合谁： 不想装任何运行时、想要干净可控、或者网络受限装不了脚本的人。

容器 / Docker

长什么样：

1

docker run -it --rm ghcr.io/anomalyco/opencode

它是什么： Docker 是一个"隔离盒子"。工具装在盒子里，不碰你的主系统。-it 表示交互式终端，--rm 表示退出后自动删除这个盒子。

优点： 干净、可复现、不污染系统；换电脑一条命令就能复原环境。

缺点： 要先装 Docker；桌面类工具不一定适合；文件路径映射要额外配置。

适合谁： 开发者、想隔离环境的人、服务器上部署的人。普通用户一般不需要。

桌面应用 / 图形安装包

长什么样： 双击 .exe、.msi、.dmg、.deb、.rpm、.AppImage。

它是什么： 不走命令行，直接图形界面安装的版本。

优点： 对不熟悉终端的人最友好；有界面，能点按钮。

缺点： 不一定有 CLI 的全部能力；更新方式各平台不同；有些工具只提供 CLI，没有桌面版。

适合谁： 完全不想碰终端的人。

从源码编译安装

长什么样：

1
2
3

git clone https://github.com/xxx/xxx
cd xxx
make && make install

或者 cargo build --release、go build。

它是什么： 拿到源代码，自己在你电脑上编译成可执行文件。

优点： 可以改代码、可以针对自己平台优化、可以装还没发布的版本。

缺点： 需要编译工具链，耗时长，升级麻烦，容易报错。

适合谁： 开发者、想改源码的人。普通用户不要选。

应用商店 / 插件市场

长什么样：

  • VS Code 扩展市场里搜插件；
  • JetBrains 插件市场里搜插件；
  • 微软商店 / Mac App Store 里搜应用；
  • 浏览器扩展商店。

它是什么： 装在某个宿主软件里的"插件版"，不是独立 CLI。

优点： 安装最简单，和宿主软件集成好。

缺点： 能力受宿主软件限制；卸载宿主软件时插件也没了；有些插件会重新创建配置文件。

适合谁： 只想在某个编辑器里用，不想单独装 CLI 的人。

一张总表：怎么选

方式 典型命令 需要预装 自动更新 适合谁
官方一键脚本 curl … | bash / irm … | iex 无 通常有 想最快装好的人
系统包管理器 brew / winget / choco / scoop / apt 对应包管理器 随包管理器 已习惯包管理器的人
语言包管理器 npm -g / pip / cargo 对应运行时 手动 已有 Node/Python/Rust 环境的人
独立二进制 下载 zip / tar.gz 无 手动 不想依赖运行时、要控版本
容器 / Docker docker run … Docker 重新拉镜像 想隔离环境、可复现
桌面应用 双击 .exe / .dmg 无 应用内更新 不想用终端的人
源码编译 git clone + make 编译工具链 手动 开发者、要改代码
应用商店 / 插件 商店里点安装 宿主软件 随宿主 只想在编辑器里用的人

一句话选择建议：

能用官方一键脚本就用官方一键脚本；被网络或系统限制卡住，再退到系统包管理器；npm 等语言包管理器作为最后选项；完全不想依赖运行时就用独立二进制；不想碰终端就用桌面应用。

术语小词典

词 意思
CLI Command Line Interface，命令行界面。就是你在终端里敲命令用的工具。
终端 / Terminal 敲命令的那个黑框或窗口。Windows 上有 PowerShell、CMD、Windows Terminal。
PATH 环境变量，告诉系统"去哪些目录找可执行文件"。配不好就会提示 command not found。
npm Node.js 的包管理器，不是安装方式本身，是"语言包管理器"这一类里最出名的一个。
irm PowerShell 里的 Invoke-RestMethod，用来从网上下载内容。irm ... | iex = 下载脚本并执行。
curl 跨平台的下载工具。curl ... | bash = 下载脚本并执行。
iex PowerShell 里的 Invoke-Expression，把一段文本当作代码执行。
二进制 / Binary 已经编译好的可执行文件，双击或敲命令就能跑。
运行时 某门语言跑起来需要的环境，比如 Node.js 是 JavaScript 的运行时。
全局安装 装到整个系统都能用，而不是只装到某个项目文件夹。npm 里用 -g 表示。
Docker 一个"隔离盒子"工具，把软件装在盒子里，不碰主系统。
仓库 / Repository 存放软件包或源代码的地方。GitHub 是最常见的代码仓库。
Releases GitHub 上"发布版本"的页面，通常放编译好的压缩包。

安全提醒

  1. 只从官方域名下载。 执行 curl … | bash 或 irm … | iex 前，先看清域名。

  2. npm 包名只认官方的。 npm 上存在同名山寨包，装错可能泄露凭证。

  3. curl | bash 的习惯： 有条件的话先下载脚本、读一遍再运行：

    1
2
3

    curl -fsSL <url> -o install.sh
less install.sh
bash install.sh

  4. 校验签名 / 校验和。 官方通常提供 SHA256 或 GPG 签名，重要工具建议校验。

  5. 谨慎使用第三方"配置切换 / 中转代理"工具。 它们常会改写你的配置文件，写入第三方地址和令牌，轻则报错，重则凭证外泄。

  6. API Key 不要提交进 Git 仓库。 一旦疑似泄露，立即到对应平台轮换。

本文档为个人整理，非官方文档。具体命令以各项目官方页面为准。
