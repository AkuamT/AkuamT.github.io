面向 Windows / macOS / Linux 的命令行（CLI）安装手册，覆盖两大 AI 编程助手。 整理时间：2026 年 10 月。命令与版本以官方文档为准，若与官方页面不一致，以官方为准。 阅读建议：只想装一个工具，直接跳到对应章节；想先了解"该不该继续用 npm"，看「先看这里」一节。

先看这里：三个最常问的问题

Q1：还需要用 npm 安装吗？

工具 结论
Claude Code 不需要。官方文档已把「原生安装器（Native Install）」列为 Recommended，npm 被挪到「Advanced installation options」。而且只有原生安装会后台自动更新，Homebrew / WinGet / npm 三条路都要手动升级。新用户不建议再走 npm。
OpenCode 可选。官方同时提供安装脚本、独立原生二进制、npm 三种方式。已有 Node.js 环境的用户走 npm 最省事；想完全不依赖 Node.js 就下独立二进制。

Q2：有原生安装包/二进制吗？

两个都有。

  • Claude Code：原生安装器一条命令搞定，不需要 Node.js，也不需要管理员权限，会自动配置 PATH 并在后台自动更新。
  • OpenCode：官方提供各平台的独立二进制（zip / tar.gz），也有安装脚本；但 Windows 上安装脚本依赖 bash 环境（WSL 或 Git Bash），官方因此在 Windows 章节首推 WSL。

Q3：三者装法怎么选？

一句话：能用官方原生安装器就用原生安装器；被网络或系统限制卡住时，再退到系统包管理器（WinGet / Homebrew / choco / scoop），npm 作为最后选项。

Claude Code 安装

系统要求

项目 要求
操作系统 macOS 13.0+ / Windows 10 1809+ 或 Windows Server 2019+ / Ubuntu 20.04+ / Debian 10+ / Alpine Linux 3.19+
硬件 4 GB+ 内存；x64 或 ARM64 处理器（不支持 32 位 Windows）
网络 必须联网
Shell Bash、Zsh、PowerShell 或 CMD
附加依赖 ripgrep——Claude Code 通常自带，若代码搜索异常见官方排障页
地区 需位于 Anthropic 支持的国家/地区

安装方式总览

方式 自动更新 适用平台
原生安装器（推荐） ✅ 后台自动 Windows / macOS / Linux / WSL
Homebrew ❌ 需手动 brew upgrade macOS / Linux
WinGet ❌ 需手动 winget upgrade Windows
Linux 包管理器（apt / dnf / apk） 随包管理器 Debian / Fedora / Alpine
npm（高级选项） ❌ 需手动升级 任意有 Node.js 的平台
桌面应用（图形界面） — Windows / macOS / Linux

原生安装命令

平台 命令
Windows（PowerShell） irm https://claude.ai/install.ps1 | iex
Windows（CMD） curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash

提示：判断自己在哪个终端——PowerShell 的提示符长这样 PS C:\>，CMD 的长这样 C:\>。两条命令不能互换：在 PowerShell 里跑 CMD 命令会报 The token '&&' is not a valid statement separator；在 CMD 里跑 PowerShell 命令会报 'irm' is not recognized。

指定发布通道或版本（参数取值：stable、latest、或具体版本号如 2.1.89，缺省为 latest）：

平台 命令
Windows（PowerShell） & ([scriptblock]::Create((irm https://claude.ai/install.ps1))) stable
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash -s -- stable

安装器背后做了什么

了解流程有助于判断"卡住了还是在干活"：

  1. 校验系统架构（拒绝 32 位 Windows）；ARM64 与 x64 自动选择对应二进制。
  2. 从 downloads.claude.ai 读取当前版本号。
  3. 下载该版本的 manifest.json，取出对应平台的 SHA256 校验和。
  4. 下载二进制到本地临时目录。
  5. 校验 SHA256，不一致则删除文件并中止。
  6. 安装到用户目录并写入 PATH。
  7. 删除临时文件，输出完成提示。

⚠️ 两个容易误判的点

  • 全程没有进度条，看起来像卡住，实际在下载，通常几十秒内完成。
  • 完成标志是一行绿色的 Installation complete!。

安装位置

平台 可执行文件 数据目录
Windows %USERPROFILE%\.local\bin\claude.exe %USERPROFILE%\.local\share\claude
macOS / Linux / WSL ~/.local/bin/claude ~/.local/share/claude

用户配置与会话数据则位于：~/.claude/（Windows 为 %USERPROFILE%\.claude）与 ~/.claude.json。

验证安装 

1
2

claude --version     # 应打印版本号
claude doctor        # 环境自检（排障首选）

重要：安装后请关闭并重新打开终端。安装器刚写入的 PATH 对已经打开的窗口不可见。

如果提示找不到命令（command not found / 无法将"claude"项识别为 cmdlet）：

1
2
3

# Windows PowerShell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"                                  # ① 二进制是否已安装
[Environment]::GetEnvironmentVariable('Path','User') -split ';' | Select-String 'local\\bin'   # ② PATH 是否包含

若 ① 为 True 而 ② 为空，手动补进用户级 PATH（无需管理员，追加即可）：

1
2

$p = [Environment]::GetEnvironmentVariable('Path','User')
[Environment]::SetEnvironmentVariable('Path', "$env:USERPROFILE\.local\bin;$p", 'User')

macOS / Linux 同理，把 export PATH="$HOME/.local/bin:$PATH" 写进 ~/.bashrc / ~/.zshrc。

首次运行与登录 

1
2

cd 你的项目目录
claude

首次启动会进入引导流程：选择登录方式（Claude 订阅账号，或 Anthropic Console 的 API Key）→ 浏览器完成授权 → 配置写入 ~/.claude/。

更新策略与发布通道

  • 原生安装：后台自动更新，无需干预。
  • 发布通道：
    • stable——稳定通道，通常比最新版落后约一周，会跳过有重大回归的版本；
    • latest——最新通道，新版本一发布就能拿到。
  • 其他方式的更新命令：brew upgrade claude-code / winget upgrade Anthropic.ClaudeCode / npm update -g @anthropic-ai/claude-code。

卸载

安装方式 卸载命令
原生（Windows PowerShell） Remove-Item -Path "$env:USERPROFILE\.local\bin\claude.exe" -Force 与 Remove-Item -Path "$env:USERPROFILE\.local\share\claude" -Recurse -Force
原生（macOS / Linux / WSL） rm -f ~/.local/bin/claude 与 rm -rf ~/.local/share/claude
Homebrew brew uninstall --cask claude-code（latest 通道则为 claude-code@latest）
WinGet winget uninstall Anthropic.ClaudeCode
npm npm uninstall -g @anthropic-ai/claude-code

清理配置文件（⚠️ 会一并删除全部设置、已授权工具、MCP 配置与会话历史）：

平台 命令
Windows（PowerShell） Remove-Item -Path "$env:USERPROFILE\.claude" -Recurse -Force；Remove-Item -Path "$env:USERPROFILE\.claude.json" -Force
macOS / Linux / WSL rm -rf ~/.claude；rm ~/.claude.json

若 VS Code 扩展、JetBrains 插件或桌面应用仍在安装状态，它们会重新创建 ~/.claude/；想彻底清除需先卸载它们。

常见问题速查

现象 原因与处理
command not found: claude / 无法识别 安装目录未进 PATH —— 重开终端；仍不行参考上面「验证安装」一节
'irm' is not recognized 你在 CMD 里执行了 PowerShell 命令
The token '&&' is not a valid statement separator 你在 PowerShell 里执行了 CMD 命令
下载超时 / Failed to get a valid version from downloads.claude.ai 网络或地区问题：配置代理后重试，例如 export HTTPS_PROXY=http://127.0.0.1:端口（Windows：$env:HTTPS_PROXY="http://127.0.0.1:端口"）
Checksum verification failed 下载损坏，重新执行安装命令
Windows 上 Bash 工具不可用 安装 Git for Windows：Claude Code 会优先使用 Git Bash，未安装时回退到 PowerShell 作为 shell 工具
装过多次、行为诡异 可能存在多个安装（如 npm 版 + 原生版并存），用 claude doctor 检查冲突安装

OpenCode 安装

官网：https://opencode.ai ｜ 仓库：https://github.com/anomalyco/opencode

注意品牌沿革：该项目原属 sst 组织，现已迁移至 anomalyco。旧链接 github.com/sst/opencode 会自动跳转，不是仿冒站点。

先搞清 V1 与 V2

OpenCode 目前有两条并行的产品线，都使用 opencode 这个命令，无法共存（不能同时安装）：

V1（stable） V2（beta）
安装脚本 curl -fsSL https://opencode.ai/install | bash curl -fsSL https://opencode.ai/v2/install | bash
npm 包名 opencode-ai @opencode/cli
Homebrew brew install anomalyco/tap/opencode brew install anomalyco/tap/opencode-v2
Windows 包管理器 支持 choco / scoop 不支持
文档 https://opencode.ai/docs https://opencode.ai/v2/docs

建议：V2 仍在 beta，且明确声明 Windows 包管理器不受支持。追求稳定请选 V1；想尝鲜再考虑 V2，并注意它与 V1 不能并存。

V1 安装方式

方式 命令
安装脚本（推荐） curl -fsSL https://opencode.ai/install | bash
npm npm install -g opencode-ai
pnpm / yarn / bun pnpm install -g opencode-ai / yarn global add opencode-ai / bun install -g opencode-ai
macOS / Linux（Homebrew） brew install anomalyco/tap/opencode
Arch Linux sudo pacman -S opencode（稳定）或 paru -S opencode-bin（最新）
Windows（WSL，官方推荐） 在 WSL 内使用上面的脚本或 npm 方式
Windows（Chocolatey / Scoop） choco install opencode / scoop install opencode
Windows（npm） npm install -g opencode-ai
Docker docker run -it --rm ghcr.io/anomalyco/opencode

V2 安装方式

方式 命令
安装脚本 curl -fsSL https://opencode.ai/v2/install | bash
npm npm install -g @opencode/cli
bun bun install -g --trust @opencode/cli
pnpm pnpm add -g --allow-build=@opencode/cli @opencode/cli
yarn yarn global add @opencode/cli
Homebrew brew install anomalyco/tap/opencode-v2
独立二进制 从官网下载页或 GitHub Releases 取对应平台压缩包

通过 npm / bun / pnpm 安装时，包内 postinstall 脚本会自动选择当前平台的原生二进制。bun 与 pnpm 默认阻止构建脚本，因此官方命令里带了 --trust / --allow-build 参数。

Windows 用户的三个注意点

  1. 官方首推 WSL：性能与功能兼容性最好。
  2. 安装脚本需要 bash：curl ... | bash 在纯 Windows 终端里跑不了，需 WSL 或 Git Bash。
  3. V2 不支持 Windows 包管理器：choco / scoop 这条路在 V2 上不通；V2 请用 npm 或独立二进制。

安装目录优先级

安装脚本按以下顺序选择落点：

  1. $OPENCODE_INSTALL_DIR
  2. $XDG_BIN_DIR
  3. $HOME/bin
  4. $HOME/.opencode/bin（默认兜底）

例：

1

OPENCODE_INSTALL_DIR=/usr/local/bin curl -fsSL https://opencode.ai/install | bash

验证与配置 

1
2

opencode --version    # 打印版本
opencode              # 在项目目录中启动 TUI

启动后在 TUI 里用 /connect 配置模型供应商（官方推荐自家 OpenCode Zen，也支持任意兼容 provider）。

卸载

  • 脚本 / 独立二进制安装：删除上一步安装目录中的 opencode 可执行文件，并从 PATH 中移除该目录。
  • npm 安装：npm uninstall -g opencode-ai（或 @opencode/cli）。
  • Homebrew：brew uninstall opencode（或 opencode-v2）。
  • 配置目录：~/.config/opencode/、~/.local/share/opencode/ 可按需删除。

桌面版（Beta）

不想用终端的话，官方也提供桌面应用：Windows 为 opencode-desktop-windows-x64.exe，macOS 为 .dmg，Linux 为 .deb / .rpm / .AppImage，下载页见官方文档。

两者对比与选择建议

维度 Claude Code OpenCode
出品方 Anthropic（官方） Anomaly 社区开源（MIT）
模型支持 主要面向 Claude 系列（也支持兼容 API 端点） 任意 provider（含本地/自建）
安装难度 极低（一条命令，自带自动更新） 中（需按平台/版本挑方式）
Windows 体验 原生支持良好（建议装 Git for Windows） 建议 WSL
是否开源 客户端闭源 完全开源
适合人群 想要"开箱即用 + 官方支持" 想要"可换模型、可自托管、可改源码"

选择建议

  • 只想尽快用起来、且有 Anthropic 账号 → Claude Code（原生安装）。
  • 想接第三方模型、想省钱、想折腾 → OpenCode（V1 stable）。
  • 两者功能定位类似，可以先都装：Claude Code 装在用户目录（~/.local/bin），OpenCode 走 npm 或独立目录，互不干扰。

安全与合规提醒

  1. 只从官方域名下载
    • Claude Code：claude.ai、code.claude.com、downloads.claude.ai
    • OpenCode：opencode.ai、github.com/anomalyco/opencode
  2. npm 包名只认官方的：npm 上存在同名山寨包（OpenCode 生态里就出现过 opcpackage 等仿制包）。Claude Code 认 @anthropic-ai/claude-code，OpenCode 认 opencode-ai（V1）/ @opencode/cli（V2）。
  3. 校验签名/校验和
    • Windows：Get-AuthenticodeSignature .\claude.exe，签名者应为 Anthropic, PBC。
    • macOS：codesign --verify --verbose ./claude。
    • 官方还提供带 GPG 签名的 manifest.json，可校验所有平台二进制的 SHA256。
  4. curl … | bash 与 irm … | iex 的安全习惯：先看清域名，再执行；有条件的话先下载脚本、读一遍再运行（curl -fsSL <url> -o install.sh 然后 less install.sh）。
  5. 谨慎使用第三方"配置切换 / 中转代理"工具：这类工具常会直接改写 ~/.claude/settings.json、~/.config/opencode/opencode.json 等文件，写入第三方 baseURL 与 token；一旦它写入失效的模型名或残留 hook，轻则启动报错，重则凭证外泄。要用就自己写配置文件，清楚每一行在做什么。
  6. API Key 管理：不要把 Key 明文提交进 Git 仓库；一旦疑似泄露，立即到对应平台轮换。
