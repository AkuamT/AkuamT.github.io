面向 Windows / macOS / Linux 的命令行（CLI）安装手册，覆盖两大 AI 编程助手。 整理时间：2026 年 10 月。命令与版本以官方文档为准，若与官方页面不一致，以官方为准。 阅读建议：只想装一个工具，直接跳到对应章节；想先了解"该不该继续用 npm"，看「先看这里」一节。

先看这里：三个最常问的问题

Q1：还需要用 npm 安装吗？

工具 结论
Claude Code 不需要。官方文档已把「原生安装器（Native Install）」列为 Recommended，npm 被挪到「Advanced installation options」。而且只有原生安装会后台自动更新，Homebrew / WinGet / npm 三条路都要手动升级。新用户不建议再走 npm。
OpenCode 可选。官方同时提供安装脚本、独立原生二进制、npm 三种方式。已有 Node.js 环境的用户走 npm 最省事；想完全不依赖 Node.js 就下独立二进制。

Q2：有原生安装包/二进制吗？

两个都有。

  • Claude Code：原生安装器一条命令搞定，不需要 Node.js，也不需要管理员权限，会自动配置 PATH 并在后台自动更新。
  • OpenCode：官方提供各平台的独立二进制（zip / tar.gz），也有安装脚本；但 Windows 上安装脚本依赖 bash 环境（WSL 或 Git Bash），官方因此在 Windows 章节首推 WSL。

Q3：三者装法怎么选？

一句话：能用官方原生安装器就用原生安装器；被网络或系统限制卡住时，再退到系统包管理器（WinGet / Homebrew / choco / scoop），npm 作为最后选项。

Claude Code 安装

系统要求

项目 要求
操作系统 macOS 13.0+ / Windows 10 1809+ 或 Windows Server 2019+ / Ubuntu 20.04+ / Debian 10+ / Alpine Linux 3.19+
硬件 4 GB+ 内存；x64 或 ARM64 处理器（不支持 32 位 Windows）
网络 必须联网
Shell Bash、Zsh、PowerShell 或 CMD
附加依赖 ripgrep——Claude Code 通常自带，若代码搜索异常见官方排障页
地区 需位于 Anthropic 支持的国家/地区

安装方式总览

方式 自动更新 适用平台
原生安装器（推荐） ✅ 后台自动 Windows / macOS / Linux / WSL
Homebrew ❌ 需手动 brew upgrade macOS / Linux
WinGet ❌ 需手动 winget upgrade Windows
Linux 包管理器（apt / dnf / apk） 随包管理器 Debian / Fedora / Alpine
npm（高级选项） ❌ 需手动升级 任意有 Node.js 的平台
桌面应用（图形界面） — Windows / macOS / Linux

原生安装命令

平台 命令
Windows（PowerShell） irm https://claude.ai/install.ps1 | iex
Windows（CMD） curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash

提示：判断自己在哪个终端——PowerShell 的提示符长这样 PS C:\>，CMD 的长这样 C:\>。两条命令不能互换：在 PowerShell 里跑 CMD 命令会报 The token '&&' is not a valid statement separator；在 CMD 里跑 PowerShell 命令会报 'irm' is not recognized。

指定发布通道或版本（参数取值：stable、latest、或具体版本号如 2.1.89，缺省为 latest）：

平台 命令
Windows（PowerShell） & ([scriptblock]::Create((irm https://claude.ai/install.ps1))) stable
macOS / Linux / WSL curl -fsSL https://claude.ai/install.sh | bash -s -- stable

安装器背后做了什么

了解流程有助于判断"卡住了还是在干活"：

  1. 校验系统架构（拒绝 32 位 Windows）；ARM64 与 x64 自动选择对应二进制。
  2. 从 downloads.claude.ai 读取当前版本号。
  3. 下载该版本的 manifest.json，取出对应平台的 SHA256 校验和。
  4. 下载二进制到本地临时目录。
  5. 校验 SHA256，不一致则删除文件并中止。
  6. 安装到用户目录并写入 PATH。
  7. 删除临时文件，输出完成提示。

⚠️ 两个容易误判的点

  • 全程没有进度条，看起来像卡住，实际在下载，通常几十秒内完成。
  • 完成标志是一行绿色的 Installation complete!。

安装位置

平台 可执行文件 数据目录
Windows %USERPROFILE%\.local\bin\claude.exe %USERPROFILE%\.local\share\claude
macOS / Linux / WSL ~/.local/bin/claude ~/.local/share/claude

用户配置与会话数据则位于：~/.claude/（Windows 为 %USERPROFILE%\.claude）与 ~/.claude.json。

验证安装 

1
2

claude --version     # 应打印版本号
claude doctor        # 环境自检（排障首选）

重要：安装后请关闭并重新打开终端。安装器刚写入的 PATH 对已经打开的窗口不可见。

如果提示找不到命令（command not found / 无法将"claude"项识别为 cmdlet）：

1
2
3

# Windows PowerShell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"                                  # ① 二进制是否已安装
[Environment]::GetEnvironmentVariable('Path','User') -split ';' | Select-String 'local\\bin'   # ② PATH 是否包含

若 ① 为 True 而 ② 为空，手动补进用户级 PATH（无需管理员，追加即可）：

1
2

$p = [Environment]::GetEnvironmentVariable('Path','User')
[Environment]::SetEnvironmentVariable('Path', "$env:USERPROFILE\.local\bin;$p", 'User')

macOS / Linux 同理，把 export PATH="$HOME/.local/bin:$PATH" 写进 ~/.bashrc / ~/.zshrc。

首次运行与登录 

1
2

cd 你的项目目录
claude

首次启动会进入引导流程：选择登录方式（Claude 订阅账号，或 Anthropic Console 的 API Key）→ 浏览器完成授权 → 配置写入 ~/.claude/。

不想用 Anthropic 官方账号？ 可以改接第三方厂商的 Anthropic 兼容端点（DeepSeek / Kimi / 智谱 GLM / 通义千问等），并直接跳过登录引导 —— 见下文「不用官方登录：接入第三方大模型 API」一节。

更新策略与发布通道

  • 原生安装：后台自动更新，无需干预。
  • 发布通道：
    • stable——稳定通道，通常比最新版落后约一周，会跳过有重大回归的版本；
    • latest——最新通道，新版本一发布就能拿到。
  • 其他方式的更新命令：brew upgrade claude-code / winget upgrade Anthropic.ClaudeCode / npm update -g @anthropic-ai/claude-code。

卸载

安装方式 卸载命令
原生（Windows PowerShell） Remove-Item -Path "$env:USERPROFILE\.local\bin\claude.exe" -Force 与 Remove-Item -Path "$env:USERPROFILE\.local\share\claude" -Recurse -Force
原生（macOS / Linux / WSL） rm -f ~/.local/bin/claude 与 rm -rf ~/.local/share/claude
Homebrew brew uninstall --cask claude-code（latest 通道则为 claude-code@latest）
WinGet winget uninstall Anthropic.ClaudeCode
npm npm uninstall -g @anthropic-ai/claude-code

清理配置文件（⚠️ 会一并删除全部设置、已授权工具、MCP 配置与会话历史）：

平台 命令
Windows（PowerShell） Remove-Item -Path "$env:USERPROFILE\.claude" -Recurse -Force；Remove-Item -Path "$env:USERPROFILE\.claude.json" -Force
macOS / Linux / WSL rm -rf ~/.claude；rm ~/.claude.json

若 VS Code 扩展、JetBrains 插件或桌面应用仍在安装状态，它们会重新创建 ~/.claude/；想彻底清除需先卸载它们。

常见问题速查

现象 原因与处理
command not found: claude / 无法识别 安装目录未进 PATH —— 重开终端；仍不行参考上面「验证安装」一节
'irm' is not recognized 你在 CMD 里执行了 PowerShell 命令
The token '&&' is not a valid statement separator 你在 PowerShell 里执行了 CMD 命令
下载超时 / Failed to get a valid version from downloads.claude.ai 网络或地区问题：配置代理后重试，例如 export HTTPS_PROXY=http://127.0.0.1:端口（Windows：$env:HTTPS_PROXY="http://127.0.0.1:端口"）
Checksum verification failed 下载损坏，重新执行安装命令
Windows 上 Bash 工具不可用 安装 Git for Windows：Claude Code 会优先使用 Git Bash，未安装时回退到 PowerShell 作为 shell 工具
装过多次、行为诡异 可能存在多个安装（如 npm 版 + 原生版并存），用 claude doctor 检查冲突安装

方式 命令

Windows 用户的三个注意点

  1. 官方首推 WSL：性能与功能兼容性最好。
  2. 安装脚本需要 bash：curl ... | bash 在纯 Windows 终端里跑不了，需 WSL 或 Git Bash。
  3. V2 不支持 Windows 包管理器：choco / scoop 这条路在 V2 上不通；V2 请用 npm 或独立二进制。

两者对比与选择建议

维度 Claude Code OpenCode
出品方 Anthropic（官方） Anomaly 社区开源（MIT）

选择建议

  • 只想尽快用起来、且有 Anthropic 账号 → Claude Code（原生安装）。
  • 想接第三方模型、想省钱、想折腾 → OpenCode（V1 stable）。
  • 两者功能定位类似，可以先都装：Claude Code 装在用户目录（~/.local/bin），OpenCode 走 npm 或独立目录，互不干扰。

不用官方登录：接入第三方大模型 API

本节讲的是 Claude Code 官方支持的机制：把请求指向你自己的 LLM 网关，或指向第三方厂商提供的 Anthropic 兼容端点（DeepSeek、Kimi、智谱 GLM、通义千问等）。它不是破解 —— 官方文档里专门有一页《Connect Claude Code to an LLM gateway》讲这件事；配好之后 Claude Code 就不再要求 Anthropic 官方登录。

原理：换一个地址 + 换一个凭证

Claude Code 只认一件事：Anthropic Messages API 协议。任何兼容这套协议的服务，只要改几个环境变量就能把底层模型换掉。

变量 作用 不配的后果
ANTHROPIC_BASE_URL 请求发往的端点 请求仍发往 Anthropic 官方，第三方 Key 鉴权失败
ANTHROPIC_AUTH_TOKEN 凭证，以 Authorization: Bearer <token> 发送 401 鉴权错误
ANTHROPIC_API_KEY 凭证的另一种形式，以 x-api-key 发送 同上（交互模式下还需一次性确认，见下文「排查表」）
ANTHROPIC_MODEL 主对话模型 报"模型不存在"
ANTHROPIC_DEFAULT_OPUS_MODEL
ANTHROPIC_DEFAULT_SONNET_MODEL
ANTHROPIC_DEFAULT_HAIKU_MODEL
ANTHROPIC_DEFAULT_FABLE_MODEL		 各档位模型映射 对应档位的任务失败
CLAUDE_CODE_SUBAGENT_MODEL 子 Agent 使用的模型 子任务失败或效果明显变差

凭证变量该用哪个？ 官方建议：不确定对方网关要哪种时，先用 ANTHROPIC_AUTH_TOKEN；若返回 401，再换成 ANTHROPIC_API_KEY（反过来同理）。两个不要同时设置。

为什么必须配"档位映射"？ Claude Code 会按场景请求不同档位的模型——主对话、后台摘要、子 Agent 等。第三方端点通常没有 haiku / sonnet / opus 这些名字，所以要把每个档位显式映射到真实模型名，否则对应场景会静默失败（表面能聊，后台任务却报错）。

  • Windows：C:\Users\<用户名>\.claude\settings.json

第 3 步：跳过首次登录引导

编辑或新建 ~/.claude.json（Windows：C:\Users\<用户名>\.claude.json），加入这一项：

1
2
3

{
  "hasCompletedOnboarding": true
}

不设置它时，Claude Code 启动后会尝试连接 api.anthropic.com 做登录校验，于是出现 Unable to connect to Anthropic services. Failed to connect to api.anthropic.com: ERR_BAD_REQUEST 这类报错。

跨平台一次写入（用 node 改 JSON，避免手改格式出错）：

配置写在哪里的区别（关键）

位置 生效范围 说明
~/.claude/settings.json 的 env 所有项目（个人级） ✅ 推荐，官方与各厂商文档都用它
shell 环境变量（export / $env:） 当前终端及其子进程 适合临时测试；但从桌面/开始菜单启动的 IDE 看不到这些变量
项目 .claude/settings.json 的 env 仅该项目 ⚠️ 它在首次运行向导和信任提示之后才生效，因此不能用来跳过登录；而且容易被提交进 git

冲突规则：settings.json 里的 env 会覆盖 shell 中同名的环境变量。 所以发现"改了环境变量却不生效"时，先回头检查 settings.json 里是不是有残留旧值。

三个容易踩的细节

验证配置是否生效

步骤 操作 期望结果
① 直测端点 curl <BASE_URL>/v1/messages --header "Authorization: Bearer <KEY>" --header "Content-Type: application/json" --data '{"model":"<模型>","max_tokens":1,"messages":[{"role":"user","content":"hi"}]}' 返回合法 JSON（{"id":"msg_...","content":[...]}），而不是 HTML 错误页
② 会话内检查 启动 claude 后执行 /status Anthropic base URL 行显示你的端点；Auth token / API key 行显示凭证来源。若显示 Login method: <claude.ai 账号> 说明凭证没送到
③ 端到端 随便发一句（如"你好"） 正常回复、无报错
④ 模型档位 /model 能看到你配置的模型

修改配置后必须新开终端窗口再启动 claude，否则读到的是旧环境。

排查表

现象 原因 处理
401 invalid_api_key 凭证类型与端点不匹配，或 Key 无效 ANTHROPIC_AUTH_TOKEN 与 ANTHROPIC_API_KEY 二选一；确认 Key 与端点属于同一家、同一套餐
model not found / 模型不存在 模型名拼错，或该模型未在套餐内开放 对照厂商文档核对模型名（注意 [1m] 后缀、大小写、多余空格）
主对话正常，但子 Agent / 后台任务报错 档位变量没配全 补齐 ANTHROPIC_DEFAULT_HAIKU_MODEL、ANTHROPIC_DEFAULT_FABLE_MODEL、CLAUDE_CODE_SUBAGENT_MODEL
改了配置不生效 旧值残留在 settings.json，或 shell 里有旧 export 清掉两端残留；settings.json 的 env 优先级高于 shell
仍提示登录 / Unable to connect to Anthropic services 变量没在"首次运行向导之前"可见，或没设 hasCompletedOnboarding 用用户级 settings.json 或 shell export；确认 ~/.claude.json 中该项为 true
每次启动都问 Do you want to use this API key 用的是 ANTHROPIC_API_KEY（交互模式需一次性确认） 选 Yes；或改用 ANTHROPIC_AUTH_TOKEN
想清除已保存的官方登录 之前 /login 过 会话内执行 /logout，然后重启
403 / 收到 HTML 错误页 前置 WAF 或反向代理拦了请求体 让网关把 /v1/messages 从请求体检查规则中豁免

重要提醒

  1. 别同时设置 ANTHROPIC_API_KEY 和 ANTHROPIC_AUTH_TOKEN，会冲突；Kimi 文档明确指出要把 ANTHROPIC_API_KEY 删掉。
  2. settings.json 里是明文 Key：不要提交进 git；项目级配置务必写进 .gitignore。
  3. .env 文件不会被读取：不要把凭证写在 .env 里。
  4. 换第三方 = 换数据去向：你的代码和对话会完整经过该厂商或中转服务，选择前想清楚；优先用厂商直营端点，慎用来源不明的"中转站"。
  5. 回到官方登录：删掉 settings.json 中 env 里的这些变量（或直接删该文件），执行 /logout，重启 claude 即可恢复官方登录流程。
  6. 第三方"一键切换"工具的取舍：见下文「用图形化工具管配置」一节 —— 它们会直接改写 settings.json，省的是操作成本，贵的是排查成本。

用图形化工具管配置（以 CC Switch 为例的取舍）

手写 settings.json 对不熟悉 JSON 的人确实有门槛，于是出现了不少"配置管理 / 供应商切换"类图形工具，其中最流行的是 CC Switch（github.com/farion1231/cc-switch，14 万+ stars，官网 ccswitch.io）。本节的分析对这一类工具普遍适用。

它们解决什么问题

  • 在图形界面里填 Base URL / API Key，不用碰 JSON，也不怕写错逗号；
  • 内置常见厂商模板（DeepSeek、Kimi、智谱 GLM、通义千问等）与自建网关；
  • 一键切换多个供应商（官方账号 ↔ 第三方账号 ↔ 便宜模型）；
  • 自动帮你写入 hasCompletedOnboarding，省掉首次登录引导；
  • 附带备份、Skills 管理、用量统计等周边功能。

对需要在多个供应商之间频繁切换的用户，这确实省事。它省的是操作成本。

需要知道的固有代价

这类工具不是"帮你改一个字段"，而是接管你的配置文件。以 CC Switch 为例，它的官方文档与 issue 里明确记录了几条"设计如此"的行为：

行为 后果
切换供应商时用完整快照重写 live 配置文件（官方在 issue #3946 明确回复"这是有意的设计行为"） 你自己写在 settings.json 里的 hooks、statusLine、permissions 等字段会被覆盖掉；同类 issue 还有 #2992 / #4274 / #2109 / #2871 / #3078
会写入自己的 hook 或环境变量，有时还附带辅助脚本 若脚本本体或解释器在本机不存在，每次启动都会报错，且报错位置离"配置"很远，极难定位
一个程序同时接管多个 CLI（Claude Code / Codex / OpenCode / Gemini / Grok / Hermes 等） 任一处错配会波及其他工具。例如写入 OpenCode 配置的路径与工具实际读取的路径不一致时，会出现"切换看似成功、实际全部落空"（issue #5945）
修改的是真实生效文件，而非副本 出问题时，第一现场就是你在用的工作配置

注意：这通常不是"软件质量差"，而是产品定位使然——接管式管理必然带来"谁的字段算数"的冲突。它确实提供备份（~/.cc-switch/backups/，以及记录首次改写前原文件的 backups/live-first-write/），但备份能救文件，救不了你排查问题时浪费的时间。

新手友好度的悖论

手写配置 图形化工具
上手成本 需要看懂一个 JSON 文件 点几下就能用
出问题时的排查 每一行都是你自己写的，范围很小 面对工具生成的一堆文件 + 被覆盖的原始配置 + 自动注入的 hook，不清楚哪一层在生效
能否脚本化排查 可以（用 diff、/status、claude doctor 逐层验证） 通常不行（纯 GUI，无命令行入口）

换句话说：它省的是操作成本，贵的是排查成本。 如果你连"配置为什么没生效"都还需要搜索，那么当工具替你写入的内容出问题时，你会更无从下手。

决策建议

你的情况 建议
只用一个供应商长期使用 手写一次配置就够，之后几个月都不用再碰。图形界面省下的几分钟，不值它带来的覆盖风险
需要在 3 个以上供应商之间频繁切换 这类工具的价值才真正体现，值得用，但请按下面「如果决定用，请这样做」的方式使用
想要极简 用上文「不用官方登录」一节的"模板 + 一条命令"，或自建"切换 = 复制一个小文件"的脚本，比 GUI 更快也更透明

如果决定用，请这样做

  1. 只让它管一个工具：用不到的 CLI（Codex / Gemini / OpenCode 等）不要打开对应面板；
  2. 关掉本地代理 / Routing：直连最少一层转发出错的可能；
  3. 关掉非必要的自动同步：Skills 同步、会话同步、插件集成都会顺手改到别的目录；
  4. 每次切换后打开配置文件看一眼（~/.claude/settings.json）：确认 env 里的模型名正确，且没有多余的 hooks 段；
  5. 记住备份位置：~/.cc-switch/backups/live-first-write/ 保存着"被改写前的原始文件"，出事从这里捞；
  6. 切换后跑一次自检（如 claude doctor）；
  7. 心里有数：以上 6 条都做下来，对单供应商用户来说，已经比手写一个 JSON 更麻烦了。

安全提醒

  • 这类工具会接触到你的 API Key 和全部配置文件，务必只从官方渠道下载。CC Switch 的官方站点是 ccswitch.io，官方仓库是 github.com/farion1231/cc-switch；GitHub 上存在多个同名 fork，下载前确认作者与地址。
  • 连推荐它的云厂商也会附上免责声明。例如阿里云百炼文档在介绍它时写道：“该工具为第三方软件，其脚本与代码不受阿里云审核和维护，安装使用前请自行评估其来源可信度与代码安全性。”
  • 无论用什么工具，最终生效的永远是 ~/.claude/settings.json。学会读这个文件，你就永远有兜底能力。

安全与合规提醒

  1. 只从官方域名下载
    • Claude Code：claude.ai、code.claude.com、downloads.claude.ai
    • OpenCode：opencode.ai、github.com/anomalyco/opencode
  2. npm 包名只认官方的：npm 上存在同名山寨包（OpenCode 生态里就出现过 opcpackage 等仿制包）。Claude Code 认 @anthropic-ai/claude-code，OpenCode 认 opencode-ai（V1）/ @opencode/cli（V2）。
  3. 校验签名/校验和
    • Windows：Get-AuthenticodeSignature .\claude.exe，签名者应为 Anthropic, PBC。
    • macOS：codesign --verify --verbose ./claude。
    • 官方还提供带 GPG 签名的 manifest.json，可校验所有平台二进制的 SHA256。
  4. curl … | bash 与 irm … | iex 的安全习惯：先看清域名，再执行；有条件的话先下载脚本、读一遍再运行（curl -fsSL <url> -o install.sh 然后 less install.sh）。
  5. 第三方"配置切换 / 中转代理"工具的取舍：详见上文「用图形化工具管配置」一节。核心是——它们会直接改写 ~/.claude/settings.json、~/.config/opencode/opencode.json 等文件，最终生效的永远是这些文件本身，所以务必会读、会改、会验证它们。
  6. API Key 管理：不要把 Key 明文提交进 Git 仓库；一旦疑似泄露，立即到对应平台轮换。
